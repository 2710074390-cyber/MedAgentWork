#### ⚠️ 新踩的坑：分视图站点的点击测试会集体超时

第一次跑浏览器测试时 **16 个 `btn.click()` 全部 `Timeout 30000ms exceeded`**，
而 URL 级检查全绿。诊断（`elementFromPoint` + `getBoundingClientRect`）：

```
rect: {x:0, y:0, w:0, h:0}   cardOpacity: 0   hitTag: NAV.nav   cardHasIn: False
```

根因：站点是**分视图**的（`.view` 容器 `view-home` / `view-junior2` / `view-senior1`，
只有激活的加 `.active`）。测试没先切视图 → 目标分区 `display:none` → 包围盒 0×0 →
命中测试打到导航栏 → 永远等不到可点击。

**修法**：点击前先 `pg.click('.nav-term[data-term="junior2"]')` 切视图，再
`card.scroll_into_view_if_needed()`。**不要用 `click(force=True)` 绕过** ——
那会掩盖"按钮真的点不动"这类真实 UX 缺陷。

（同理：`scripts/check_site_links.mjs` 抽的是数据数组，不受视图影响，所以它一直是绿的。）

### 追加：给 `deploy_site.ps1` 加回退保护闸（commit `f868e01`）

**风险确认**：`deploy_site.ps1:62` 是 `git worktree add $worktree HEAD` —— 它部署的是**本地提交**。
而本地 `main` = `9dd9aac` 仍含 4 处路径双重拼接 bug、`大四上/复习资料/*.pdf` 仍是脚本打印件。
**所以一次本地部署会把线上刚修好的东西全部打回原形。**

改动：新增 `-Force`；部署前 fetch 并比较本地 `$Commit` 与 `origin/<Branch>`：
本地落后 → exit 2 拒绝；一致/超前 → 放行；**取不到远程或 sha（离线 / git 不在 PATH）→ 同样 exit 2（fail-closed）**。
用 `FETCH_HEAD` 而非 `origin/<Branch>` 引用 —— 本机 `refs/remotes` 写入被拦截（坑 2），FETCH_HEAD 不受影响。

**验证**（把闸的代码文本逐字抽出来跑，不触碰真实部署命令）：

| 用例 | 条件 | 结果 |
|---|---|---|
| stub1_behind | 落后 3 个提交 | exit 2 拦截 ✅ |
| stub2_uptodate | 与线上一致 | exit 0 放行 ✅ |
| stub3_ahead | 本地超前 | exit 0 放行 ✅ |
| case4_git_missing | git 不可用（真实条件） | exit 2 拦截（fail-closed）✅ |
| case2_force | git 不可用 + `-Force` | exit 0 放行 ✅ |

**限制（如实记）**：本机脚本宿主（PowerShell 工具）**沙箱内不能执行 git.exe**
（`Get-Command git` 返回空、`& git.exe --version` 返回空，即使 PATH 里有 `C:\Program Files\Git\cmd`），
所以「落后/一致/超前」三例只能用**桩 git** 验证控制流，无法用真实 git 端到端跑。
fail-closed 与 `-Force` 两例是在真实「git 不可用」条件下跑的。
