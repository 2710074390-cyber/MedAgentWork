## 片一 · 五阶段管线（约 40s，键 `pipeline`）

**钩子（0–7s）**
- eyebrow：`01 / 五阶段管线`
- h2：为什么不让一个模型一口气写完？
- sub：一个 Agent 从零写到成册，速度快，但没人知道它在哪一步跑偏了。

**A 拍 · 拆角色（7–17s）**
- 标题：拆成五个角色，各管一段
- 要点（逐条入场）：
  - 编排（MedMaster）先回显意图：科目 / 目标题数 / 模块划分，你确认才动手
  - 出题 MedGen → 中间产物落盘
  - 质检 MedQC → 质检报告
  - 修复 MedFix → 最终产物
  - 成册 MedReview → 复习资料
- 底部：每一步都有可读的文件，不存在「只在对话里」的状态

**B 拍 · 契约与门禁（17–29s）**
- 标题：契约先行，门禁强制
- 决策 1：每个阶段的输入输出写成 schema，产物摄入时就校验（jsonschema）
  - 避坑：格式漂移——上一阶段少一个字段，下一阶段整批返工
- 决策 2：批次状态机原子写入 + 血缘记录；门禁不过就地 HALT，不允许带病往下走
  - 避坑：并发写覆盖（save.py 的 lost-update）与半成品进发布
- 决策 3：BLOCKED → 回退对应 Agent 修完重跑门禁，而不是手工往下推

**C 拍 · 证据与收束（29–40s）**
- 证据条：`5 阶段` `4 道门禁` `1 个状态机` `人确认后才开工`
- 收束句：慢一点，但每一步都算得清。

**音**：0s 低频起 → 7s 铃（B 拍入场）→ 17s 铃（契约拍）→ 33s 收束铃 → 37s 起淡出。

## 片二 · 质量门禁（约 42s，键 `gate`）

**钩子（0–7s）**
- eyebrow：`02 / 质量门禁`
- h2：让模型检查自己，靠谱吗？
- sub：模型很会解释，但它也是被检查的对象。所以判定必须交给代码。

**A 拍 · 机械规则（7–20s）**
- 标题：能被规则抓住的，先用规则抓
- 三条真实规则（逐条入场）：
  - `R9 数值缺单位` —— 0.5 与 0.5mg 只有一个对（WARN → FAIL）
  - `R2 正确选项显著更长` —— 答案长就是错答案的典型破绽
  - `R6 数值区分度` —— 四个选项数值挨得太近，等于没给区分度
- 补：`R10 词重复线索 / R11 收敛策略`按 NBME 出题习惯反向排除

**B 拍 · 事实与门禁（20–33s）**
- 标题：事实也要机械核对
- 决策 1：`fact_check` 页码反查——引用能翻回原书的那一页，才算数
  - 避坑：段落跨页断链，PDF 来源对不上
- 决策 2：GoldenSet 9,616 条真题解析做交叉验证，考研原题逐条比对
  - 避坑：内容看着专业，答案却与真题库冲突
- 决策 3：`FAIL == 0` 才放行；`gate_check` 不合格直接拒绝部署

**C 拍 · 证据与收束（33–42s）**
- 证据条：`R1–R13 硬规则` `D1–D20 质检维度` `90 项测试 + 164 项巡检`
- 撤回（暖色）：批次 039 的 199 题主动撤回，待并集后再发
- 收束句：不是让模型更准，是让错误出不来。

## 片三 · 个性化学科 RAG（约 38s，键 `rag`）

**钩子（0–7s）**
- eyebrow：`03 / 个性化学科 RAG`
- h2：23 个学科，能用同一套检索吗？
- sub：不能。方剂组成、影像分期、数值参考值，压根不是一类东西。

**A 拍 · 分块与检索（7–20s）**
- 标题：分块按学科走，检索双通道
- 决策 1：逐科分块策略——方剂组成不切碎，跨表结构按语义保护规则保形
  - 避坑：一刀切分块把表格和对照表切坏，检索回来是碎片
- 决策 2：向量 + 关键词混合检索，再 rerank 收一次
  - 避坑：只上向量，药名、数值这类字面精确的查询召不回来

**B 拍 · 成本与红线（20–30s）**
- 标题：检索既要稳，也要算得过账
- 决策 3：查询结果与 embed 双层磁盘缓存，同查询零调用
  - 真实事故：batch027 期间余额不足（402），管线一度卡死
- 决策 4：余额不足时 `--no-rerank` 降级——成本约减半，管线不中断
- 红线（暖色）：校准难度 `calibrated_p` 是先验估计，不是实测；宁可标记待审，不静默覆盖

**C 拍 · 证据与收束（30–38s）**
- 证据条：`23 学科独立配置` `26 个索引` `混合检索 + 重排`
- 收束句：检索到的质量，决定了后面所有的质量。
