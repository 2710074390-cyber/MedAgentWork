## 执行摘要

### 三个最关键的结论



1. **"无标注原图 + 程序叠加中文标注" 是目前唯一可靠的工业级方案。** 所有文生图模型（包括最新的 Ideogram 4、Qwen-Image-3.0）在中文医学标注上均无法达到 100% 准确 ——Qwen-Image-3.0 的中文一级字准确率虽达 97.29%，但医学术语零容错要求必须走 "图 - 文分离" 工作流。这已是视觉文字研究领域的明确共识。你项目中现有写实图的英文标注乱码（如 "Mucius-bicorrboate layer"）正是这个问题的直接体现。

2. **AI 生成写实医学插图的解剖准确性严重不足，>99% 的图片含虚构解剖。** 多项同行评审研究证实：手外科研究发现 >99% 的 AI 图含虚构结构；足部骨骼标注正确率 0-57%；冠状动脉起源经常错误。"看起来对"≠"是对的"。所有写实图必须经过医学专业人员审核，这是不可跳过的环节。但 AI 在概念示意图 / 流程图领域表现良好（AI 可生成性 ★★★★★），可高效生产。

3. **render\_review.py 当前不支持图片语法，这是管线集成的第一缺口。** 图片行 `![图N：标题](images_v2/xxx.png)` 会被当成普通段落，链接被解析成 `<a>` 标签，实际不显示图片。必须先扩展渲染器，再谈规模化插图。同时 27 张图共 24.4MB（单张 3.5MB），压缩至 1600px + WebP q=82 后可降至约 3.5MB（-86%）。

### 推荐方案一句话

> **通义万相 Qwen-Image-3.0（主力底图，0.14-0.18 元 / 张）+ 即梦 Seedream 5.0（写实风格补充 + 局部修正）+ Pillow 自动标注叠加 + 两级人工质检 + render_review.py 图片扩展 + WebP 压缩部署**
> 15 科 × 50-100 张 = 750-1500 张最终图，生成成本约 ¥500-900，核心瓶颈是人工质检时间（预计 15-25 小时 / 科的关键图审核）。

### 1.2 经典写实插图标杆

**🥇 Netter（奈特解剖）—— 写实风格定义者**



* 风格：自然主义写实，"写实但不琐碎"（realism without the clutter of confusing minutiae）

* 全图谱统一色彩编码：**红色 = 动脉，蓝色 = 静脉，黄色 = 神经**

* 临床视角构图（外科医生打开体腔看到什么）

* 第 9 版已引入数字艺术家延续 Netter 传统，证明写实风格可迁移到数字 / AI 辅助生产

* 来源：[https://netterreference.com/content/netter\_atlas\_9e/assets/pdf/FM9eForNetRef.pdf](https://netterreference.com/content/netter_atlas_9e/assets/pdf/FM9eForNetRef.pdf)

**🥈 Robbins Pathology—— 写实 + 概念双轨制**



* 三重插图体系：世界级概念插图（发病机制可视化）+ 显微照片 + 大体标本照片

* 第 10 版含 1,600 幅全彩插图

* **最值得借鉴**：每张写实主体图配一张机制示意图 —— 写实图展示 "是什么"，概念图展示 "为什么"

* 概念示意图恰好是 AI 最擅长的领域（可生成性 ★★★★★），形成 "AI 高效生产概念图 + 人工审核写实图" 的混合工作流

* 来源：[https://www.us.elsevierhealth.com/robbins-cotran-kumar-pathologic-basis-of-disease-9780443264528.html](https://www.us.elsevierhealth.com/robbins-cotran-kumar-pathologic-basis-of-disease-9780443264528.html)

**🥉 AMBOSS——Image Overlay 交互式标注**



* "Most medical images don't come with captions. Ours do."

* 标注层与底图分离，可交互、可切换、可更新 —— 在 Markdown/HTML 环境中可通过 CSS/SVG 实现类似效果

* 来源：[https://www.amboss.com/us/features](https://www.amboss.com/us/features)

### 1.5 一张好的写实医学插图的构成要素

综合 Netter、Robbins、Gray's、SciDraw 指南提炼：



* **构图**：一图一概念；信息密度 5-7 个元素（人脑短期记忆 7±2）；临床视角；选择性简化（对抗 AI 的 "超现实主义" 过度细节）；≥30% 留白用于标注

* **标注**：统一标注（结构名直接标在图上，不用编号 + 脚注）；标签用名词不用句子；引导线不用箭头；标签在轮廓外；中英文双语；字体 12-14px

* **色彩**：全系列统一解剖色彩编码（红 = 动脉 / 蓝 = 静脉 / 黄 = 神经）；3 主色 + 1 强调色，不超过 4 种；红色慎用（= 血 / 危险）；蓝 / 青绿 / 暖灰为安全色

* **分辨率**：彩色图 ≥300dpi，线描 ≥600dpi，显微图必须含比例尺

* **系列一致性**：规模化生产前必须定义 Style Sheet（调色板 / 线条粗细 / 标签样式 / 图标体系 / 风格 Prompt 模板）

### 2.5 两套可直接复现的端到端流程

#### 流程一：国内工具链（推荐）



```
知识点YAML → 批量提示词生成 → 通义万相API生成无字底图 → 自动初筛

→ 人工质检(解剖准确性) → Pillow叠加中文标注 → 终检 → WebP压缩 → 嵌入MD
```



1. **准备知识点列表**（knowledge\_points.yaml）：每个知识点含 subject/view/structures/pathology/emphasis/filename

2. **批量生成提示词**：用固定 STYLE\_PROMPT 前缀保证风格一致，LLM 辅助填充结构名称

3. **调用通义万相 API**：百炼平台，`wanx2.1-t2i-turbo` 0.14 元 / 张，每知识点生成 2-3 张候选

4. **自动初筛**：Python 脚本过滤纯黑 / 纯白 / 明显崩坏图，可用 CLIP 评分排序

5. **人工质检**：对照教材检查解剖准确性（核心瓶颈，预计通过率 40-60%）

6. **Pillow 标注叠加**：YAML 驱动，相对坐标 (0-1)，编号圆圈 + 引导线 + 圆角文字框 + 图例

7. **WebP 压缩**：缩至 1600px + q=82，单张从 3.5MB 降至约 130KB

8. **嵌入 MD**：`![图N：标题](images/webp/filename.webp)`

#### 流程二：国际工具链（追求最高解剖准确性）



```
DALL-E 3 API生成无字底图 → 即梦智能画布局部修正 → Pillow标注 → 同上
```



* DALL-E 3 HD $0.08/张，Standard $0.04 / 张

* 需稳定代理，OpenAI API Key 需海外支付

* 对解剖结构错误但构图好的图，用即梦智能画布局部重绘修正

## 第三层：医学准确性与质控 ——AI 图的 "可信度陷阱"

### 3.1 学术证据：AI 医学插图的准确性问题

这是调研中**证据最充分、结论最一致**的部分：



| 研究                     | 模型 / 工具                         | 核心发现                                           |
| ---------------------- | ------------------------------- | ---------------------------------------------- |
| 2023, PubMed 37694692  | 多个文生图模型                         | 无一能生成全面准确的解剖细节。颏孔 / 眶上孔经常缺失，冠状动脉起源错误，脑沟回关系错误   |
| 2025, J Clin Medicine  | MJ v6, DALL-E 3, Gemini, SD 2.0 | 颅面解剖任务，所有模型均有局限，解剖学家 5 分制评估                    |
| 2025, PMC12547223（手外科） | AI 文生图工具                        | **>99% 的 AI 生成图片含虚构解剖**，图像清晰度优秀但解剖和标注不准确       |

| 2024, Cureus（眼科）       | DALL-E                          | 能生成可识别的眼睛，但**缺乏教育价值**，LASIK/PRK/SMILE 手术步骤不准确  |
| 2024, 西安红会医院撤稿         | Midjourney                      | 大鼠长出**四个睾丸**，细胞信号图与电路板雷同，论文被撤稿                 |

**核心结论**：AI 生成医学插图在**视觉外观**上已达到高写实度，但在**解剖准确性**上严重不足。高视觉可信度常与高错误率并存 ——"看起来对" 不等于 "是对的"。当前阶段，AI 生成写实图必须经过医学专业人员审核修订才能用于教育。

### 3.4 推荐的高准确性工作流（3D 金标准路线）

对于解剖准确性要求最高的图（如心脏冠脉、神经系统、手术入路），推荐：



```
BodyParts3D/OpenAnatomy 导出3D模型 → Blender渲染指定视角 → 获得"金标准"线稿/深度图

→ ControlNet(depth/canny)加载金标准 → Qwen-Image/SD上色风格化

→ SAM-Med2D自动分割验证(IoU>0.8) → 专家清单审核 → Pillow标注
```

此路线通过 3D 模型保证解剖结构正确，AI 只负责风格化渲染，从源头降低虚构解剖风险。

### 4.1 AI 生成图像的版权归属

**中国：**



* "春风案"（2024）：利用 AI 生成图片时，如能体现人的**独创性智力投入**（参数设置、多次调整、选择判断），应认定为作品，受著作权法保护

* 2026 年 4 月案例：简单一键生成、无人工干预的图片，因 "生成高度依赖 AI 软件"，未达到独创性标准，不受保护

* Thaler v. Perlmutter（2026 年 3 月最高法院确认）：**纯 AI 生成作品不享有版权**，版权只保护人类创意产出

## 第五层：管线集成与工程化

### 5.1 第一缺口：render\_review.py 不支持图片语法

**根因定位**：



* `convert_block()` 逐行解析，图片行不匹配任何特殊块，落入普通段落分支

* `parse_inline()` 中链接正则 `r'\[([^\]]+)\]\(([^)]+)\)'` 会把 `![alt](path)` 中的 `[alt](path)` 匹配成 `<a>` 标签

* 结果：图片变成 `!<a href="...">图N：标题</a>`，不显示图片

**6 处修改方案**：



1. `parse_inline()`：在链接正则之前添加图片语法处理



```
text = re.sub(r'!\\\[(\[^\\]]\*)\\]\\((\[^)]+)\\)', self.\_replace\_image, text)
```



1. **新增&#x20;**`_replace_image()`**&#x20;回调**：将 `![alt](path)` 替换为 `<figure><img><figcaption>` 结构，支持 `--embed-images` base64 内联模式，自动从 alt 中解析 "图 N：标题" 格式

2. `convert_block()`：在普通段落分支之前添加独立图片行检测，作为块级 `<figure>` 处理

3. `__init__()`：添加 `embed_images: bool = False` 参数

4. **CSS**：添加 `.med-figure` 样式（居中、圆角、阴影、`break-inside: avoid` 打印不跨页、`.fig-caption` 图注样式）

5. `main()`：添加 `--embed-images` 命令行参数

### 5.2 base64 内联 vs 外部引用



| 维度       | base64 内联                    | 外部引用        |
| -------- | ---------------------------- | ----------- |
| 自包含性     | ✅ 单文件包含一切                    | ❌ 需图片同目录    |
| HTML 体积  | 24.4MB 图→base64 后约**32.5MB** | HTML 仅几百 KB |
| Pages 部署 | ❌ 超 25MiB 单文件限制              | ✅ 图片单独部署    |
| PDF 打印   | ✅ 离线可用                       | 需图片已缓存      |
| 修改图片     | ❌ 需重新渲染整个 HTML               | ✅ 替换文件即可    |

**结论**：Cloudflare Pages 部署用外部引用；本地 PDF 打印用 `--embed-images` 生成自包含 HTML。

### 5.3 图片压缩：24.4MB → 3.5MB



| 格式                | 参数       | 27 张图预期体积    | reduction |
| ----------------- | -------- | ------------ | --------- |
| PNG（原图 2K）        | -        | 24.4 MB      | 0%        |
| PNG（缩至 1600px）    | optimize | \~12 MB      | \~51%     |
| **WebP q=82（推荐）** | 1600px   | **\~3.5 MB** | **\~86%** |
| WebP q=75         | 1600px   | \~2.5 MB     | \~90%     |
| AVIF q=60         | 1600px   | \~2.2 MB     | \~91%     |



* 分辨率从 2K/4K 缩至 1600px 是最大单项收益（内容区仅 720px 宽，2x 屏够用）

* WebP q=82 在医学插图上肉眼几乎无损，浏览器兼容性好

* 1600px 宽在 A4 打印时相当于 225 DPI，满足打印质量

* AVIF 比 WebP 再小 20-30%，但编码慢 5-10 倍，建议作为 `<picture>` 可选格式

### 5.4 标注叠加工程方案（Pillow，可直接运行）

核心设计：



* **数据驱动**：标注信息存储在 YAML 中，与图片分离，修改标注不需重新生成图

* **分辨率无关**：坐标使用相对比例 (0-1)

* **标注元素**：编号圆圈 + 折线引导线 + 圆角文字框 + 图例

* **自动避让**：`side` 参数（left/right/top/bottom/auto）将文字框放在结构外侧

标注 YAML 示例：



```
image: images/raw/heart\_coronary.png

output: images/annotated/heart\_coronary.png

style:

&#x20; font: "Microsoft YaHei"

&#x20; font\_size: 28

&#x20; number\_circle\_radius: 18

&#x20; number\_bg: "#dc2626"

annotations:

&#x20; - id: 1

&#x20;   point: \[0.35, 0.42]       # 相对坐标

&#x20;   label: "左冠状动脉"

&#x20;   side: "left"

&#x20; - id: 2

&#x20;   point: \[0.62, 0.38]

&#x20;   label: "右冠状动脉"

&#x20;   side: "right"

legend:

&#x20; position: "bottom-right"

&#x20; items:

&#x20;   - { color: "#dc2626", label: "动脉" }

&#x20;   - { color: "#2563eb", label: "静脉" }
```

完整可运行代码（\~300 行，含编号圆圈 / 折线引导线 / 圆角文字框 / 图例 / 自动布局）见子报告 `AI医学插图生态调研与工程集成方案.md` 第三章。

字体选择：Windows 自带微软雅黑（`C:/Windows/Fonts/msyh.ttc`）为默认推荐；开源跨平台用思源黑体（Noto Sans CJK SC）。


命名规范：`{器官/系统}_{主题}_{病理/状态}.webp`，全小写下划线分隔，不使用中文文件名（避免 URL 编码问题）。

### 5.6 与 5-Agent 管线的集成

现有管线：MedMaster → MedGen → MedQC → MedFix → MedReview



| Agent         | 集成点                                             |
| ------------- | ----------------------------------------------- |
| **MedMaster** | 大纲中标注 "需要插图" 的知识点，生成 knowledge\_points.yaml 雏形  |
| **MedGen**    | MD 中插入图片占位符 `![图N：标题](images/webp/{name}.webp)` |
| **MedQC**     | 新增检查：引用的图片是否存在、alt 格式是否合规、标注 YAML 是否对应、图片体积是否超标 |
| **MedFix**    | 修复缺失引用、修正标注坐标、重新生成不合格图                          |
| **MedReview** | 调用扩展后的 render\_review.py，可选 `--embed-images`    |

**建议新增 MedIllustrator Agent**（位于 MedGen 和 MedQC 之间）：读取知识点列表 → 调用 API 批量生成原图 → 人工审核 → 生成标注 YAML → 标注叠加 → 压缩转换。

### 5.7 Cloudflare Pages 优化



* 部署产物仅含 HTML + 内联 CSS/JS + `images/webp/*.webp`，总计约 4MB

* `_headers` 文件配置图片长缓存：`Cache-Control: public, max-age=31536000, immutable`

* `<img>` 标签含 `loading="lazy" decoding="async"`

* 排除 `images/raw/` 和 `images/annotated/` 不部署

* 可选 `<picture>` 提供 AVIF/WebP 双格式

## 推荐落地路径

### 阶段一：打通管线（1-2 天）



1. **扩展 render\_review.py**：添加 `![alt](path)` 图片支持 + `--embed-images` 参数 + `.med-figure` CSS

2. **压缩现有 27 张图**：Pillow 批量缩至 1600px + WebP q=82，24.4MB→3.5MB

3. **更新 MD 引用路径**：`images_v2/xxx.png` → `images/webp/xxx.webp`

4. **验证渲染**：生成含图 HTML，确认图片正常显示，打印 PDF 确认清晰度

### 阶段二：搭建工具链（1 周）



1. **实现 annotate\_image.py**：Pillow 标注叠加工具（YAML 驱动，编号 + 引导线 + 文字框 + 图例）

2. **实现 batch\_prompts.py**：从知识点 YAML 批量生成结构化提示词

3. **实现 optimize\_images.py**：批量压缩转换脚本

4. **注册通义万相 API**：获取 Key，用四类模板各生成 5 张测试图，评估医学写实质量

5. **为现有 27 张图创建标注 YAML**：重新叠加正确的中文标注（替换现有乱码英文标注）

### 阶段三：试点学科（2 周）



1. **选择 1 个学科做端到端试点**（建议外科学或解剖学相关模块，20-30 个知识点）

2. **建立质检标准文档**：使用第三层的 35 项质检清单，明确 A/C 类一票否决

3. **跑通完整流程**：知识点→提示词→生成→质检→标注→压缩→嵌入→渲染→PDF

4. **评估通过率和时间**：统计质检通过率、单张平均耗时，优化提示词模板

### 阶段四：规模化推广（4-8 周）



1. **按学科批量生产**：每科 50-100 张，优先核心考点（内科学已完成可补充，待生成的传染病 / 眼科 / 口腔同步进行）

2. **新增 MedIllustrator Agent**：集成到 5-Agent 管线

3. **建立两级质检体系**：医学生初筛 + 学科专家终审关键图

4. **Cloudflare Pages 部署优化**：配置缓存、懒加载、排除原图

5. **所有 AI 生成图添加 "AI 生成" 标识**，保留创作过程记录

### 关键决策汇总



| 决策点       | 推荐选择                        | 理由                                       |
| --------- | --------------------------- | ---------------------------------------- |
| 主力绘图工具    | 通义万相 Qwen-Image-3.0         | 中文理解最准，API 最便宜 (0.14-0.18 元 / 张)，医学验证案例多 |
| 写实风格补充    | 即梦 Seedream 5.0             | 写实质感强，智能画布支持局部修正解剖错误                     |
| 标注方式      | Python Pillow 程序叠加          | AI 中文标注错误率 8.2%-37%，程序叠加 100% 准确且可迭代     |
| 图片格式      | WebP q=82, 1600px           | 浏览器兼容性好，-86% 体积，肉眼无损，225DPI 满足打印         |
| HTML 图片模式 | 外部引用 (部署) + base64 内联 (打印)  | Pages 25MiB 限制，本地打印需自包含                  |
| 质控底线      | A/C 类一票否决 + 两级人工审核          | >99% AI 图含虚构解剖，人工审核不可跳过                  |
| 版权策略      | 开源模型优先 + 完整创作记录 + AI 标识     | 降低训练数据侵权风险，满足中国法规                        |
| 高准确性图     | 3D 模型渲染金标准 + ControlNet 风格化 | 从源头保证解剖结构正确                              |
