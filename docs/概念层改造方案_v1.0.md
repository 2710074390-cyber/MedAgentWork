## 1. 目标结构：一层三边一状态

```
节点    KC（概念卡）：kc_id / display_id / module / title / keypoints / pages / weight / status
边①     measures   题 × KC，多对多，role=primary|differential|related，**每条带 evidence**
边②     prereq     KC → KC，单向，DAG，basis=page_order|module_order|manual
边③     ref        KC ↔ KC，无向，basis=same_keypoint|same_page
状态    mastery / last_review / interval / due   ← 由站点学习器写入，不进仓库
```

**边的证据规则（硬约束）**：每条边必须能回答"凭什么连"。
- `measures`：evidence = 该 KC 标题在题干/解析/逐项解析中出现的原文片段
- `prereq`：basis = `page_order`（同模块按教材页序相邻）或 `module_order`（模块链）
- `ref`：basis = `same_keypoint`（共享教师重点条号）或 `same_page`（页码重叠）
- 答不出证据 → 不建这条边。宁可图稀疏，不可图失信。

## 3. 工作包

### W1 建图 `scripts/build_concept_graph.py`（新增）

| 项 | 内容 |
|---|---|
| 输入 | `中间产物/*/pilot/kc_registry.json`、`archive/中间产物/*/pilot/kc_registry.json`、`kc_question_map.jsonl` |
| 处理 | ① 自动发现注册表；② **从 `display_id` 重解析模块**（修 F1）；③ 归一 `kc_id = {subject}:{display_id}`；④ 合并节点；⑤ 由 `blueprint_weights` 填模块权重；⑥ 按 `weight/hub` 排序 |
| 输出 | `question_bank/concept_graph.json`（节点 + measures 边 + 统计，prereq 留空待 W3） |
| 验收 | 节点数 = 48 + 85 = 133；急诊 48 张卡模块分布恢复到 M01–M08；无 `M00` |

### W2 多概念标注 `scripts/label_concepts.py`（新增）

| 项 | 内容 |
|---|---|
| 方法 | **纯规则、带证据，不调模型**：对每道题，把同科所有 KC 标题（长度 ≥4 字）拿去匹配 `explanation` / `learning_value.per_option[].why` / `teacher_anchor`；命中即候选二级概念，`role=differential`，`evidence` 存命中句 |
| 主概念 | 优先用 `kc_question_map.primary_kc`；缺失则用 `teacher_anchor` 最长匹配 |
| 上限 | 每题最多 3 个概念（1 主 + 2 次），避免"全连" |
| 输出 | `question_bank/concept_labels.jsonl`（一题一行）+ 回写 `concept_graph.edges.measures` |
| 验收 | A2/A3/A4/X 的多标签率 **≥ 60%**；每条 measures 边 `evidence` 非空；`role=primary` 恰好 1 条/题 |

> 为什么不用 LLM：200 题用标题匹配就能覆盖大半，且每条边有原文可查；调模型反而不可复核、成本高、还会编关系。模型留给"标题匹配不到的疑难题"做人工队列。

### W3 前提边 `scripts/build_prereq.py`（新增，或并入 W1 的 `--prereq`）

| 项 | 内容 |
|---|---|
| 规则 | ① 同模块内按 `source_pages` 首页升序，相邻成边（i→i+1），`basis=page_order`；② 模块链：M(k) 末卡 → M(k+1) 首卡，`basis=module_order` |
| 为什么这样建 | 教材页序 + 模块序都是**客观存在的外部顺序**，可复核；且天然无环（全序子链），不需要"断环"这种脏操作 |
| 限制 | 只连相邻，不连全序（否则 48 节点会有 1128 条边，图失去信息量） |
| 人工覆盖 | 支持 `question_bank/concept_prereq_overrides.json`（手工加/删边，写明理由） |
| 验收 | 边数 ≈ 节点数 − 模块数（线性链）；**环 = 0**（拓扑排序通过）；每节点 ≥1 条 prereq 或明确标 `root=true` |

### 8.3 与计划的五处偏差（都写清原因）

1. **W3 并入 W1**。卡级前置边改为「阅读顺序」，真正的学习门控放在新增的 `module_prereq`。
   原因：卡级全序链深度达 **84**，若当硬前置，"学第 85 张卡需先掌握 84 张"，学习空间永远为空。
   现在的口径：卡级边用于阅读顺序与错题归因；模块级边（7 层）才是"能不能学下一模块"的门控。

2. **W2 的 60% 目标未达成，且判断为不该强行达成**。
   急诊 4.9% 的根因不是匹配器弱，而是**数据结构性单标签**：急诊 48 张卡对 61 条锚点近似一一对应，
   题目按 HC-20「一题一锚点」生成，解析文本也不复用卡片标题，事后推断拿不到第二概念。
   ENT 能到 55%，靠的是 **42 条「同锚点被多卡拥有」**——这是 ENT 注册表天然有的结构。
   结论：**多标签是生成期属性，不是后处理属性**。要真正到 60%，必须改 `schemas/agent2_output.schema.json`，
   让 A2/A3/A4/X 出题时就填 `concepts[]`（主 + ≥1 鉴别）。本期不在事后硬造边。

3. **C3 重新定义**。原计划 C3 = "每卡至少 1 题"，实测发现 4 张 ENT 卡 `status=active` 但 `question_ids` 为空
   （注册表状态过期，不是图的缺陷），若判 FAIL 会误伤。改为：
   C3 = **每题有主概念**（未映射 >2% FAIL，>0 WARN）；新增 **C7 = 无题卡**（WARN，提示改 status 或补题）。

4. **C4 的 FAIL 阈值从 <5% 改为 =0**。急诊 4.9% 恰好卡在 5% 线下，但"低"不等于"失效"，
   零才是信号缺失。现口径：0 → FAIL；0–60% → WARN 并写明原因。

5. **概念卡目录与文件名改用学科全称/前缀**。`急诊-K-M01-001.md` 而非 `K-M01-001.md`：
   K-ID 在 ENT 与急诊里各有一套（都叫 K-M01-001），裸名会让 Obsidian 出现同名歧义。
   同时把 `check_obsidian.py` 的 `DEFAULT_GLOBS` 增加一级 `Obsidian产物/*/*/*.md`，
   否则这批二级子目录里的卡片永远落在门禁盲区。
