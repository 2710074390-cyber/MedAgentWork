# 产物格式规范（v1.2 · 2026-10-19 押题卷改 MD 修订）

> 本文件是 **MedAgentWork 线 → 线上站（med-review-site.pages.dev）** 之间唯一的产物形态契约。
> 所有 Agent / 脚本 / 人工流程必须遵守；与站端渲染器（`index.html` 的 `mdToHtml` v2）配套。
> 违反本规范的产物视为**不合规**，`scripts/verify_produce_rules.py` 会拦截。

---

## 1. 三张表的产物形态（强制）

| 产物 | 管线/脚本最终输出 | 网站呈现 | 允许扩展名 | PDF 由谁产出 |
|------|-----------------|---------|-----------|-------------|
| **押题卷** | 仅 **MD**（`scripts/paper_builder.py` 导出 `押题卷_{科目}_{N}题.md`；题型归一为 单选题/多选题/判断题） | 刷题软件导入（「大四上刷题」）/ 网页查看 | `.md` | **一律人工**（用户手动上传；管线不产出押题卷 PDF） |
| **题库** | **MD + HTML**（MD：MedFix `ALL_questions_FIXED.md` 等；HTML：`render_qbank_html.py`） | 卡片下载/网页查看 | `.md` `.html` | **一律人工**（用户手动上传） |
| **复习资料** | **MD + HTML**（MD：MedReview 主文档；HTML：`render_review.py` 渲染） | 在线预览（mdToHtml）/ 网页版 | `.md` `.html` | **一律人工**（用户手动上传） |

其它说明：
- 押题卷的机器可读源（`最终产物/押题卷_*_N题.json`）是**生产中间物**，不是交付物，不进入站点目录；**交付物是同名 `.md`**。
- `大三下/`、`大四上/`（网站上架目录）内**禁止出现**白名单之外的文件类型（`.docx`/`.txt`/`.json` 等一律不允许）；PDF 由人工导出后上传。
- **任何脚本不得生成/写入站点目录内的 PDF**（`weasyprint`/`pdfkit`/`chrome --headless=new --print-to-pdf` 输出到 `大三下/`、`大四上/` 均违规）。
  - **为什么**：脚本渲染会**重新排版**（封面、分页、字体与人工导出版不同），且产物 `/Creator` 带 `HeadlessChrome` 指纹。
    2026-09-12 `export_review_pdfs.py` 就是这样把用户 09-01 的人工导出版覆盖掉的，站点上一直挂着脚本打印件。
  - **强制点**（2026-09-28 起）：
    - `scripts/export_review_pdfs.py` 的 `--out-dir` 落在站点目录 → 硬拒（exit 2）；
    - `scripts/verify_produce_rules.py` 对站点内每个 PDF 断言 `/Creator` 不含 `HeadlessChrome`，且体积 ≤ 25 MiB；
    - 注意：**不能用 `/Producer=Skia/PDF` 判别** —— Chrome 打印对话框与 Obsidian 内置导出同样是 Chromium `printToPDF`，人工导出版也是 Skia。

## 2. 押题卷 MD 契约（paper_builder / 题型归一）

- 交付物 = 单文件 MD（`大三下/押题卷/{科目}押题卷_{年}.md` 或 `大四上/押题卷/…`），供「大四上刷题」（MedKit 网页版）等刷题软件导入。
- 生成入口：`python scripts/paper_builder.py --subject {科目} --count {N} [--md-out …]` —— JSON 为机器可读源，MD 为交付形态。
  **HTML 交付已下线**：`quiz_template.html` / `render_*_html.py` 仅历史遗留，新产物不再使用。
- 结构（与题库 MD 同族，便于刷题软件本地规则导入）：

  ```markdown
  # {科目}押题卷（{N}题）

  > 组卷口径：考频权重 × 难度配平（calibrated_p） | 生成：{YYYY-MM-DD HH:MM}
  > 题型分布：单选题×a、多选题×b、判断题×c

  ---

  ## {模块/系统}（n题）

  ### 1. [单选题｜理解] {qid}

  > 模块：{系统}｜页码：{source}

  **{题干}**

  - A. {选项}
  - **B. {选项}** ✅

  **答案：B**

  解析：{解析}

  ---
  ```

- **题型标签（强制三值）**：`单选题` / `多选题` / `判断题`。映射：A1/A2/A3/A4/B1 → 单选题；X → 多选题；判断 → 判断题。
- **判断题**固定两选项 `正确` / `错误`，答案 `A` / `B`。
- **答案**为大写字母串（多选如 `ABD`），行格式 `**答案：X**`。
- 标题 / 元信息行**禁止**出现 `统一模板`、`v1.x`、`TEST`、内部代号。

## 3. 复习资料 MD 语法契约（与 mdToHtml v2 匹配）

MedReview 输出 MD 仅允许以下语法（站端渲染器 `mdToHtml` 支持的全部能力）：

- 标题 `#`~`######`（层次 ≤ 4 推荐）；空行分段
- **行内**：`<b>加粗</b>`、`<i>斜体</i>`、`` `代码` ``（v1.1 起禁用 `**加粗**`/`*斜体*`：Obsidian 实时预览与原生 PDF 导出按 CommonMark 解析不认中/日/韩文字符相邻的强调标记，裸 `**` 泄漏；站端 mdToHtml 与 render_review.py 同时**向下兼容**旧 `**`）
- **行内导出保真（E4 · 2026-10-15）**：因强调写在 HTML `<b>` 上，**打印样式必须**对 `b,strong` 显式 `font-weight:700 !important` 且字体字面落到**有真粗体**的字体（雅黑/思源黑）；**禁止**正文只落在无粗体字面的宋体系（SimSun/宋体）——否则 Obsidian/Chromium 导出 PDF 时**内联加粗会整体消失**（实测：PDF 里 `<b>` 段落字体为 SimSun 常规，标题因显式 font-weight 仍是雅黑粗体）。同时打印样式须全局 `print-color-adjust: exact`（含 `-webkit-`）且字体栈带 emoji 字体，保 🔴🟡🟢 **彩色**。落地实现：`scripts/obsidian-snippets/medagentwork-print.css` 的 `@media print` §7.0；回归防护：`tests/test_obsidian_snippet.py`；导出后须人工抽检（V16）
- **块**：标准 Markdown 表格（`| a | b |` 形式）、``` 代码块（ASCII 图放这里）、
  `---` 分隔线、普通引用 `> 文本`
- **Obsidian Callout**：`> [!WARNING|TIP|INFO|SUCCESS|NOTE] 标题`（连续 `>` 行组成卡片；
  站端渲染为 `.callout-{type}` 样式卡）
- **展开区**：`#### 🔬 展开：{名称}` 标题 + 普通 MD 内容（v1.1 起禁用 `<details>`/`<summary>`——Obsidian 阅读视图与原生 PDF 导出不渲染 HTML 块内部 Markdown；标题内容默认可见、全管线兼容；站端渲染器对旧 `<details>` 仍向下兼容）
- **列表**：`- ` 无序、`1. ` 有序（渲染为 `<ul>/<ol>`）

**禁止（站端不支持 / 会泄漏为文本）**：
- Mermaid 代码块（一律用 **ASCII 图**，放置于 ``` 代码块内）
- 行内强调 `**…**` / `*…*`、折叠区 `<details>` / `<summary>`（v1.1 起；旧产物保留兼容渲染，新产物禁止）
- `</?b>` / `</?i>` 之外的任意其它 HTML 标签（`<span>`/`<img>`/`<table>` 手写等）
- YAML front matter（`---` 文件头 + 元数据块）
- 流程标记：`📦 复习资料批次 X/Y`、`✅ 批次完成`、`⏭️ 下一批`、`本批产出/统计`、
  `V1-V14 视觉质量自检报告` 等（内部自检材料移动到 `质检报告/`，不进交付物；
  交付前用 `clean_produce_markup.py` 清理）

## 4. 统一渲染链（写入即适配）

| 环节 | 唯一入口 | 禁止并行入口 |
|------|---------|-------------|
| 押题卷导出 | `scripts/paper_builder.py`（JSON 源 + MD 交付，题型归一 单选/多选/判断） | `quiz_template.html` / `render_interactive_html.py` / `build_html_final.py` / `render_predict_html.py`（HTML 交付已下线，历史遗留勿用） |
| 复习资料 MD→HTML | `知识库素材/render_review.py` | 其它手写转换器 |
| 站端在线预览 | `index.html` 内 `mdToHtml`（无需联网） | 另起第三方渲染库（保持零依赖） |

## 5. 发布流程（新批次 / 新产物）

1. 产出原始文件（按上表形态）；
2. 运行 `python scripts/clean_produce_markup.py`（清除流程残留、成品化副标题）；
3. 需要网页版的复习资料运行 `render_review.py` 重渲 HTML；题库如需 HTML 运行 `render_qbank_html.py`；
4. 运行 `python scripts/verify_produce_rules.py`（FAIL==0 才算通过）；
5. 检查 `index.html` 卡片数组（EXAMS/BANKS/REVIEWS）的 meta（题数/大小/描述）与实际文件一致；
6. **PDF 一律由人工导出后上传**（押题卷/题库/复习资料均如此；脚本禁止生成）：
   - **导出**：Obsidian（Better Export PDF，带页码/书签）或 Chrome 打印对话框；导出后放到
     `大三下/题库/`、`大四上/复习资料/`、`大四上/题库/` 对应位置。
   - **体积**：Cloudflare Pages 单文件上限 **25 MiB**。超限时**只压图、不重排**：
     ```bash
     python scripts/shrink_pdf.py <你导出的.pdf> -o "大四上/复习资料/<同名>.pdf"
     ```
     该脚本只重压内嵌图片（PNG→JPEG），**页数、封面、分页、字体、书签全部保持原样**，
     并逐页像素级验证「没有重排版」。**不要**改用 `export_review_pdfs.py` —— 那是重新渲染。
   - **校验**：两道，都要跑
     ```bash
     python scripts/verify_produce_rules.py     # ① 形态/来源：≤25 MiB 且 /Creator 不含 HeadlessChrome
     python scripts/audit_site_pdfs.py          # ② 逐字节：站点上这份到底是不是你导出的原件
     ```
     `verify_produce_rules.py` 只能断言「不是脚本生成的」；**回答不了「是不是我导出的那个文件」**。
     `audit_site_pdfs.py` 拿站点每个 PDF 与人工导出目录（默认 `Desktop\大四上`、`Desktop\大三下`）
     的候选件做 sha256 比对，四档判定：✅ 逐字节相同 / 🟡 同页数但内容不同（只压图处理过，符合预期）/
     ⚠️ 页数不同（疑似旧版本或不同内容，需人工确认）/ — 无候选件。
7. `git add` 对应文件 → push（GitHub Actions 自动部署 Cloudflare Pages）。

## 6. 站端渲染器能力速查（mdToHtml v2）

支持：h1-h6 / 表格 / 代码块 / 行内 code / 粗体（`<b>`，兼容旧 `**`）/ 斜体（`<i>`，兼容旧 `*`）/ 引用 / Callout 五型 / h4 展开区（兼容旧 details 折叠区）/
有序无序列表 / hr。不支持：Mermaid、脚注、任务列表（`- [ ]`）、数学公式。
