# MedAgentWork 站点再设计 · 问题分析与改进方案

> 审计对象：仓库根 `index.html`（2091 行，单文件含全部 CSS / JS / 数据）
> 审计日期：2026-10-16 · 产出物：`index-v2.html`（仓库根，可直接对比预览）

---

## 一、现状概述

本站是「医学复习资料库」单页应用：三个学期视图（主页 / 大三下 / 大四上）通过 Tab 切换，核心功能为 **网页刷题、题库 PDF 下载、复习手册在线阅读与打印、MedKit 软件下载**。视觉走「深黑蓝 + 玻璃拟态 + 粒子特效」的极客路线，零外部依赖、纯静态、GFW 友好——这个技术路线是对的，再设计予以保留。

> 注：需求中提到的「预约 / 查询 / 资讯」属于医疗机构网站的典型功能；本站实际核心功能是「刷题 / 下载 / 研读 / 软件」，方案按本站真实功能做信息架构优化，同时引入的搜索、路由、状态反馈机制对未来扩展通用。

## 二、问题清单

### 2.1 美观性

| # | 问题 | 位置 / 证据 | 影响 |
|---|------|------------|------|
| A1 | 纯黑底 `#0a0a0a` + 大面积玻璃模糊，整体偏「黑客终端」，医学场景的信任感、洁净感不足 | `:root` L19-43 | 第一印象偏冷峻，与「医学资料库」的权威感错位 |
| A2 | 正文辅助色对比度不足：`--text-2: rgba(255,255,255,0.55)`、`--text-3: 0.47`，小字号（11–13.5px）下低于 WCAG AA 4.5:1 | L28-29 及全站 12px meta 文本 | 低视力用户与移动设备强光环境下可读性差 |
| A3 | 学科图标使用 Emoji（🫀🔪🧠⚡），跨平台渲染不一致（Windows/Android/iOS 风格迥异），与医学专业感不符 | 数据层 BANKS/REVIEWS 各条目 | 视觉语言不统一，显得不够正式 |
| A4 | 无字体层级系统：标题字重 500、正文字号散落各处（11/12/12.5/13/13.5/14.5/15/16.5…），数字与中文混排无等宽数字处理 | 全站 | 排版节奏感弱，统计数字抖动 |
| A5 | 只有暗色主题，无亮色选项；长时间阅读复习资料时暗底白字易疲劳 | 整站 | 研读场景（核心场景之一）体验欠佳 |

### 2.2 实用性

| # | 问题 | 位置 / 证据 | 影响 |
|---|------|------------|------|
| B1 | **视图不可寻址**：学期切换是 JS 视图切换 + `goTerm()` 定时器滚动（L1807-1810），URL 不变化。无法分享「大四上题库」的直接链接，刷新后回主页（仅有 localStorage 记忆），浏览器前进/后退失效 | L1798-1811 | 信息架构最大的硬伤：16 张资源卡藏在二级视图里却无一有独立 URL |
| B2 | 导航链接用 `onclick="goTerm(...);return false;"`，禁用了中键新标签打开、右键复制链接等原生行为 | L844-851 | 违背 Web 平台惯例，可访问性差 |
| B3 | **无搜索/筛选**：7+9 科题库、7+9 册手册共 32 张卡，只能靠滚动浏览找科目 | 四个 grid | 目标明确的用户（「我要找传染病学」）路径过长 |
| B4 | 首屏 Hero 终端窗口对学生用户是「装饰性拟物」，真正的三步指南藏在第二个 Tab 里，默认不可见 | L947-981 | 新手引导曝光不足 |
| B5 | 移动端导航牺牲较大：桌面 6 个导航项收缩进汉堡菜单后，「刷题」这一最高频入口没有常驻快捷方式 | L737-794 | 移动端转化路径变长 |
| B6 | 模态预览无焦点管理：打开后 Tab 键逃逸到背景页面，屏幕阅读器无播报；打开时背景仍可滚动 | L1607-1625 | 可访问性缺陷 |

### 2.3 稳定性

| # | 问题 | 位置 / 证据 | 影响 |
|---|------|------------|------|
| C1 | **三条独立 rAF 循环常驻**：星域、ASCII 雨、MW 粒子各跑一个 `requestAnimationFrame`（L1889/2021），即便 FX 关闭、标签页隐藏、Hero 滚出视口，循环仍在空转 | L1868-1893, L1976-2023 | 低端机持续耗电/发热；`fx.on=false` 时只是不绘制但每帧仍做判断 |
| C2 | `resize` 事件无防抖（L1892, L2024），每次触发都重建粒子家点数组（上千次对象分配）；`document` 级 `mousemove` 无节流（L1655） | 同上 | 窗口调整期间掉帧 |
| C3 | 网络请求无超时：`fetch('https://api.github.com/...')`（L1724）与 `fetch('/api/visits')`（L2078）在网络劣化时会长时间挂起，版本号区域卡在「正在获取版本…」 | L1720-1743, L2064-2088 | 国内访问 GitHub API 失败率高，无兜底时限 |
| C4 | DOM 访问无防护：`document.getElementById('atom-wrap').style.opacity=...`（L2048）等元素缺失即抛错中断整段 JS | 多处 | 单点故障放大 |
| C5 | 自研正则 Markdown 解析器边界情况多：嵌套列表、表格内 `\|`、CRLF 已修但无序/有序混合列表仍会串扰；行内 `*` 正则对含 `*` 的医学剂量写法（如 `2*10^9/L`）有误伤风险 | L1470-1534 | 复习手册是核心内容，渲染错误直接损害可信度 |
| C6 | 打印用 `document.write`（L1600, L1619）写入新窗口——已被 Chrome 标记为干扰性 API，且对 `about:blank` 的 popup 在部分浏览器策略下被拦 | L1594-1604 | 打印 PDF 链路有失效风险 |
| C7 | 2091 行单文件：样式、数据、逻辑、文案耦合，改一处需全量回归；无缓存策略说明（`_headers` 存在但未覆盖静态资产指纹化） | 整文件 | 维护成本高，迭代风险大 |
| C8 | 无全局错误兜底：任何一处运行时异常都会静默中断后续初始化（如卡片渲染在 FX 初始化之前，顺序倒置会白屏） | script 单块顺序执行 | 故障不可感知、不可恢复 |

## 三、改进方案与实现对照

再设计产物为 **`index-v2.html`**（仓库根目录，与现站同目录故资源相对路径约定不变，可直接部署或改名替换）。全部外部依赖为零，保持 GFW 友好。

### 3.1 美观性 → 「临床深蓝 Clinical Deep Blue」设计系统

| 改进 | 实现 |
|------|------|
| A1 信任感配色 | 底色从纯黑 `#0a0a0a` 调整为带蓝相的深海军蓝 `#0b1220` 系；主色保留品牌蓝但提亮为 `#5b8def`→`#7aa5f8` 渐变；新增「临床青」#2dd4bf 作为成功/可用语义色，克制使用 |
| A2 对比度达标 | 文本三级色提升为 100% / 78% / 60% 不透明度，全部 12px+ 文本 ≥ 4.5:1；`prefers-contrast: more` 下再提一档 |
| A3 SVG 图标系统 | 内置 20 枚描边风格 SVG `<symbol>` 精灵（heart/scalpel/brain/bolt/chat/leaf/tooth/eye/virus/cross…），学科卡片全部替换 Emoji；跨平台像素级一致 |
| A4 字体层级 | 定义 `--fs-xs(12) → --fs-3xl(clamp 40-64)` 七级字号阶、三个字重、统计数字统一 `font-variant-numeric: tabular-nums` |
| A5 双主题 | 新增亮色主题（白底 + 深蓝文字 + 同一品牌蓝），导航右侧一键切换，localStorage 持久化，默认跟随 `prefers-color-scheme`（首次访问亮/暗随系统，医学研读场景默认更友好） |

### 3.2 实用性 → 可寻址 + 可检索的信息架构

| 改进 | 实现 |
|------|------|
| B1 哈希路由 | 视图与锚点全部 URL 化：`#/s2/banks`、`#/s1/reviews-s1` 可直接分享、刷新保持、前进后退可用；旧 `#banks` 等哈希自动迁移兼容 |
| B2 原生链接 | 导航全部改回真实 `href="#/s2/banks"`，中键/右键/复制链接恢复正常；JS 只做增强 |
| B3 即时搜索 | 题库区与手册区各加搜索框，输入即过滤（按科目名/简介/标签），空结果有提示态；支持拼音首字母懒得起名——按子串匹配即可 |
| B4 新手引导前置 | Hero 右侧终端默认 Tab 改为「三步上手」（原第二个 Tab），命令演示退居次 Tab |
| B5 移动端快捷入口 | 窄屏时导航右侧常驻一个胶囊形「刷题」主按钮；汉堡菜单保留完整导航 |
| B6 模态焦点陷阱 | 打开时焦点进模态、Tab 循环锁在其中、Esc 关闭、关闭后焦点还原来源按钮；`aria-modal`/`role=dialog` 补齐；打开时锁定背景滚动 |

### 3.3 稳定性 → 性能与容错硬化

| 改进 | 实现 |
|------|------|
| C1 单一动画驱动 | 星域+ASCII+MW 粒子合并进**一个 rAF 主循环**；IntersectionObserver 监测 Hero 出视口即停绘；`document.hidden` 停绘；FX 关闭时循环整体挂起而非空转 |
| C2 事件治理 | resize 统一 150ms 防抖；mousemove 走 rAF 节流（每帧最多处理一次）；全部滚动/指针监听 `{passive:true}` |
| C3 请求超时 | 封装 `fetchWithTimeout(url, ms)`（AbortController）：GitHub API 6s、访问计数 5s，超时/失败均有兜底文案，版本号区域不会卡死；GitHub 结果写 sessionStorage 缓存，本次会话不重复请求 |
| C4 DOM 防护 | 所有元素访问经 `el &&` 或可选链；FX 开关等操作先判存在 |
| C5 解析器加固 | Markdown 解析器保留原契约（callout/details/表格），修复有序+无序列表相邻串扰；行内 `*` 强调增加边界断言，避免误伤 `2*10^9/L` 这类剂量写法 |
| C6 打印链路 | 弃用 `document.write`，改用 Blob URL + iframe 打印（同源、无弹窗拦截风险），失败时回退弹窗方案 |
| C7 工程化分层 | v2 内部按 `设计令牌 / 组件 / 视图 / 数据层 / 服务层 / 交互层` 分区注释，数据数组与渲染彻底分离；报告末尾附可选的拆分路线（css/js 外置 + 指纹化 + `_headers` 缓存） |
| C8 全局兜底 | `window.addEventListener('error')` + 初始化分片 try/catch：任一模块失败不影响其余模块，并在控制台分级输出；卡片渲染最先执行，特效最后初始化 |

### 3.4 附：部署侧建议（不动代码即可获得）

1. `_headers` 增加 `大三下/**`、`大四上/**` 静态资源 `Cache-Control: public, max-age=604800`（PDF/MD 一周内强缓存，内容更新时改文件名或加 `?v=`）。
2. 若后续拆分 css/js，文件名加内容指纹（`app.8f3a2c.js`）并配 `max-age=31536000, immutable`。
3. 保留现有「链接门禁同时断言 Content-Type」的教训——v2 的下载链路继续走原生直链，不做 fetch 中转。
