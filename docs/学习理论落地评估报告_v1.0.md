# MedAgentWork × 八条学习理论：落地评估与改造路线 v1.0

> 日期：2026-10-27　｜　依据：`MedAgentWork-理论规格清单.md`（8 条理论 + 统一数据模型 + 验收清单）
> 方法：先读清单 → 盘查本项目数据层（schema / KC 注册表 / 题库 / Obsidian 库 / 押题卷 / SRS 脚本）→ 用实测数字定位缺口 → 给可门禁化的改造项
> 结论口径：**只推荐能变成「字段 + 边 + 门禁」的改动**，不做无法验收的功能堆叠

---

## 一、一句话结论

这 8 条理论看着像 8 个功能，落到本项目其实只指向**一件事**：你已经有题（6,490）、有卡片（K-ID）、有页码、有难度先验，但**没有一层「跨批次的概念层」把它们连起来**。

- 已有的：题卡、复习卡、教材页码、考频权重、KC 注册表（**只在单批次 `pilot/` 目录里**）
- 缺的：概念层的**三类边**（双向链接 / prereq / Q 矩阵多标签）+ **一个状态**（mastery / due）
- 因此：理论 1、3、4 是「已经有了骨架但没通电」；理论 5、6 是「完全空缺」；理论 7 是「试点已跑通但没产品化」；理论 8「已经做到，应转为卖点」

**如果只做一件事**：把各批次 `kc_registry.json` 合并成全库 `concept_graph.json`，并给 A2/A3/A4/X 题补多概念标签。这一步同时解锁理论 5、6、7，且**不改任何 UI**。

## 二、现状体检：六个带数字的发现

| # | 发现 | 实测证据 | 影响的理论 |
|---|------|----------|-----------|
| 1 | **概念层是半成品**：KC 注册表存在，但只活在单批次 pilot 目录，无跨批次合并、无 `prereq` 字段 | `中间产物/batch043/pilot/kc_registry.json` 48 张卡；`scripts/` 全目录搜 `prereq|mastery|学习空间` **0 命中** | 5 |
| 2 | **Q 矩阵退化成 1:1**：200 题 → 48 个 KC，**一题多概念的题数 = 0** | 统计 `kc_registry.json`：`multi-KC questions = 0`，KC 平均挂 4.2 题 | 6 |
| 3 | **复习资料是「零链接长文」**：87k / 64k 字的主复习资料，wikilink 数 = 0 | ENT 87,358 字 / 0 条；急诊 64,440 字 / 0 条；全库 805 篇 MD 仅 70 篇有链接（8.7%），**K-ID 形式链接 0 条** | 1、3、4 |
| 4 | **作答数据按卷隔离**：localStorage key 里带卷名，5 套卷互不可见 | `RECORD_KEY = 'maw-quiz-record-' + PAPER_META.title` | 6、7 |
| 5 | **两套题号互不相认**：押题卷 `NK-A1-001` vs 题库 `batch043-M01-A1-001` | 押题卷 HTML 内 qid 前缀为学科缩写；registry / 最终产物为 batch 前缀 | 6、7（**隐藏阻塞点**） |
| 6 | **SRS 停在试点**：真 SM-2 实现已存在，但默认路径硬编码 batch040，FSRS 只有「预留接口」 | `scripts/spaced_schedule.py` 的 `DEFAULT_*` 全部指向 `batch040/pilot`；docstring 写「SM-2 为试点基线；保留 FSRS 适配接口」 | 7 |

### 判断

- 发现 1+2 是**同一件事的两面**：概念层没建起来，所以「一题多概念」既没地方存、也没人要求。
- 发现 3 是**性价比最高的缺口**：卡片已经有 K-ID（急诊资料里出现 70 次 `K-M\d\d-\d\d\d`，但全在说明表格和标题里，**一次都没写成 `[[...]]`**）。改造成本是一段正则，收益是 Obsidian 图谱 + 反链面板 + 站点侧邻接表同时激活。
- 发现 5 必须先修，否则发现 4 的数据再多也汇总不到概念上——**这是路线里最容易低估的一步**。

## 三、逐条判定：做、做到什么程度、哪些不做

| 理论 | 判定 | 在本项目的落点 | 关键约束 / 反建议 |
|------|------|----------------|-------------------|
| 1 超文本 · 双向链接 | **直接做（P0）** | 卡片标题 `### [[K-M01-001]] 急诊五级分诊`；站点侧由 `concept_graph.json` 的邻接表渲染 | 注入后必须跑 `vault_audit.py` 验断链；`check_keypoint_coverage.py` 的落点行正则只认 `📌 重点原文（第X条）` 前缀，改标题前先小样本验证不破锚点 |
| 2 认知弹性 CFT | **有条件做（P1）** | 给卡片加 `lens`（机制/临床/诊断/处置/误区/数值）；每个 KC 至少挂 2 类节点（卡 + 题 + 病例情境） | **打标签 ≠ 多视角**。CFT 要的是「同一材料换情境重访」，检验方式是同一 KC 的两次出现必须换题面/换格式——这正好对应 Pan & Rickard 的迁移条件（终测换格式时迁移最大） |
| 3 联通主义 | **已完成 ~70%（P0 补一刀）** | 三层 MOC + 按用途导航已经是「连接优先」的正确形态；补 `hub_score = 入链数 × 考频权重` 用于排序 | 不要为「图谱好看」造边；边必须有证据（页码 / 原文 / 题目映射三选一） |
| 4 Zettelkasten | **部分做** | 原子化停在「一个 KC 一卡」这一层，唯一 K-ID 已有 | **反对**把 87k 字复习资料拆成一句话一卡：医学知识是「病理生理→临床→诊断→治疗」的强叙事链，拆碎会破坏 CFT 需要的概念景观 |
| 5 KST 前提 DAG | **做（P0 建图，P1 消费）** | `prereq` 有向边 + 拓扑校验；学习空间查询；错题沿链归因 | 医学概念天然带环（心衰→水钠潴留→心衰加重）。解法：机制解释图允许环，**`prereq` 只建「学习顺序图」**，遇环断最弱一条边并记录 |
| 6 CDM / Q 矩阵 | **做，但降级（P0 标注，P1 估计）** | A2/A3/A4/X 强制 ≥2 个 concept（主概念 + 鉴别概念）；`concepts: [{kc_id, role}]` | **不做 DINA/DINO 参数估计**：个人使用场景样本量不足，参数不可识别。用计数式 + 置信度折扣即可 |
| 7 测试效应 + 间隔重复 | **做，换算法（P1）** | SM-2 → FSRS-6 默认权重；队列产品化；错题重置时同时换 lens | FSRS 权重优化需要 ≥1,000 次复习，**先不优化**，用默认先验；<100 次复习时退回 SM-2 |
| 8 本地存储优先 | **已完成，转卖点** | 押题卷纯 localStorage、站点无第三方脚本、已支持 JSON 导出 | 清单把它列为「待做」，实际是现成优势。跨设备迁移靠文件，不靠账号 |

### 一个必须写清的设计判断

清单第 6 条给的掌握度规则是「答错 −0.1，连续 3 次正确 +0.05」。方向对，但**缺一个前置条件**：Rowland (2014) 的编码阈值显示，当首次提取正确率低于 50% 时测试效应接近消失（g≈0.03）；有反馈时效应才升到 0.73。

所以对本项目的落地含义是：**新概念第一次不能直接考，要先给「讲解卡」再给「考核卡」**。你已有的 `learning_value.correct_rationale` + `per_option.why` 恰好就是这份讲解，只是目前**和 SRS 队列没有连接**。把「讲解卡 → 考核卡」做成队列里的两段，是这套理论在这个项目里最具体的一次落地。

## 四、改造路线

### P0 · 数据层（零新依赖，纯加工）

| # | 动作 | 产物 | 验收指标 |
|---|------|------|----------|
| 1 | 合并各批次 KC 注册表为全库概念图，加 `prereq`（先空）与 `hub` 字段 | `question_bank/concept_graph.json` | 节点 ≥ 48（急诊）；边：ref ≥ 2×节点、measures ≥ 200 |
| 2 | A2/A3/A4/X 题补多概念标签（先 batch043 的 200 题试跑） | 最终产物 JSON 加 `concepts[]` | 多标签率（A2 及以上）**≥ 60%**，且 `multi-KC > 0` |
| 3 | 从「模块序 + 页码序」自动推导 prereq 候选，LLM 只在同模块内确认/否决（每模块 ≤ 15 卡，成本可控） | `prereq` 边 + 拓扑报告 | **环 = 0**；prereq 边 ≥ 0.8×节点 |
| 4 | 批量注入 K-ID 双向链接 | 复习资料 MD（不破锚点） | K-ID wikilink **≥ 1/卡**；`vault_audit.py` 断链 = 0 |

### P1 · 学习器 MVP（单文件 HTML，离线）

| # | 动作 | 说明 |
|---|------|------|

## 五、特色化：三个能对外讲的点

1. **错题归因，而不是错题本**
   市面题库几乎都只给「错题重刷」。给「答错 → 沿前提链定位缺口 → 回到该补的那张卡」的极少。这一屏最有辨识度，也最符合项目已有的叙事（「不是让模型更准，是让错误出不来」——同样的话可以套到学习上：**不是让你多刷题，是让漏洞藏不住**）。

2. **多视角回访（旋转镜头）**
   BPA 卡片已有 🎯/🧬/🔗/⚖️/🚨/🩺 六个视角槽位，本质就是 CFT 的多视角材料。现在它们是长文档里的段落，做成「同一概念换镜头」的交互，是把已有内容重新编排，不是新造内容——成本低、观感强。

3. **内容云端生产，学习数据留在本地**
   这是与「AI 生成」叙事形成反差的点：内容由五阶段管线在云端批量生产，作答记录只在你浏览器里，导出即文件。清单第 8 条不是待办，是现成的差异点。

## 六、清单本身要改的四处（事实校正）

写进对外文案前必须改，否则会被懂行的人抓住：

1. **Adesope 2017 的数字不是「30–50% 保持率」**。真实结果是：总体 g = 0.61，对重读 g = 0.51（118 篇 / 272 个效应量）。"30–50% 提升"是二手转述。补充 Rowland 2014：有反馈 g = 0.73，无反馈 g = 0.39；首次正确率 <50% 时效应消失——**这条对设计是硬约束，不是脚注**。

2. **属性层级五结构的归属错了**。Q 矩阵确实出自 Tatsuoka (1983)，但「线性/收敛/发散/无结构」这套 attribute hierarchy 是 **Leighton, Gierl & Hunka (2004)** 的 attribute hierarchy method；且基本型是 4 种，「独立/混合/高阶」是后续扩展。清单把两者并到 Tatsuoka 名下。

3. **`1min→1h→1d→3d→7d→14d` 不是 SM-2**。SM-2 是 1d → 6d → 按 EF 递增。清单给的是一张自定义阶梯表，可用，但别叫 SM-2。项目里 `spaced_schedule.py` 用的是真 SM-2；要对标业界应直接上 FSRS-6（Anki 25.07 起为默认调度器，同保留率下约少 20–30% 复习量）。

4. **「每概念 ≥2 类引用节点」是建议阈值，不是理论硬性要求**。真正可检验的 CFT 落地是「同一概念在不同情境/格式下被重访」，计数只是代理指标。写成「理论要求」会过度承诺。

## 七、风险与三条反建议

- **不做 DINA/DINO 全参数估计**。个人刷题场景的作答量撑不起 Q 矩阵标定，EM/MCMC 估出来的参数不可识别，比计数式更不可信。
- **不把复习资料原子化到「一句话一卡」**。会破坏叙事链，也会让 `check_keypoint_coverage.py` 的锚点体系失效。
- **不在 P0 阶段动 UI**。数据没对齐前做界面，等于给空表画皮肤——发现 5（题号不通）就是这一条的现实版本。

**最大的真实风险**不是技术，而是**边造得没有证据**。图谱一旦允许「看起来相关就连」，三个月后没人敢信它。所以 `check_concept_graph.py` 必须能对每条边回答「证据是什么」，答不出就删边。

## 八、结论

这套清单的价值不在「8 条理论」，而在它提醒了一件事：**你的管线管到了题和锚点，但没管到「概念」**。题是可替换的，锚点是一次的，只有概念是跨批次累积的资产。

把概念层补上，等于把「一次性交付物」变成「可复利的知识资产」——这也是唯一能同时改善**产物质量**（多标签 + 前提顺序让题目设计有结构）和**产品特色**（归因 + 多视角 + 本地优先）的改动方向。
