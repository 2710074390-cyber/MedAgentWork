# MedAgentWork 质量管控规范（HC-25）

> 版本：v1.2.0 · 生效：2026-10-27 · 主责：MedMaster（编排者）
> 单一事实来源：`scripts/quality_policy.json`（阈值/档位）· `scripts/quality_gate.py`（阶段门禁）
> 适用范围：所有**新批次、新版本、重新生成的产物**。已签收旧批次与既有产物**冻结、不追溯、不回改**。

---

## 0. 目的与三条底线

**目的：** 把 T1–T6 已验证的能力（基线冻结、KC 双向映射、题目学习价值层、12 维文档评分卡、advisory/enforce 门禁）固化为可复用的项目标准，确保后续每一批、每一版都能稳定达到同一质量水平。

**三条底线：**

1. **旧产物不动**：已签收批次、已发布 PDF/HTML、既有题库与复习资料不因新标准被回改；如需增强，另开新批次或显式修订单。
2. **门禁不可跳过**：R0–R4 每个阶段必须有显式结论（PASS/WARN/BLOCKED/SKIPPED）；SKIPPED 不等于 PASS。
3. **标准可执行**：每条标准必须绑定脚本、阈值、报告路径；不能只写在文档里。

### 1.1 门禁适用范围矩阵（2026-10-26 加固）

批次可在 `workflow_state.json` 显式声明 `product_types`（`question_bank` / `prediction_paper` / `review_material`，可多选）；缺失时由 `gate_check.infer_product_types` 按产物形状推断。门禁只对具有管辖权的产物生效，避免“对题库查资料附录”一类假阻断。

| 门禁 | 题库 | 押题卷 | 复习资料 |
|---|---|---|---|
| GATE-A2 选项校验 | 必过 | 必过 | 不适用（SKIP） |
| GATE-A3 质检 + Bloom | 必过 | 必过 | 不适用（SKIP） |
| GATE-A4 修复溯源 + MD | 必过 | 必过（接受 `*押题*.md`） | 不适用（SKIP） |
| HC-24 学习价值层 | v2 必过 | v2 必过 | 不适用 |
| HC-9/10/11 资料附录 | 不适用 | 不适用 | 必过 |
| 最终 JSON 有效性 | 必过 | 必过 | 不适用 |

- `--stage auto` 按矩阵路由：复习资料批次直达 final；v2 题库/押题卷批次在 A4 后自动插入 `learning_value`，不会跳过。
- `GATE-FINAL-LEARNING-VALUE`（12 维评分卡）默认 `off`；正式发布使用 `--learning-value-mode enforce`。
- 不适用项必须在 `sub_gates` 显式记录 SKIPPED 及原因；**不得把 SKIP 当成 PASS**。

## 2. 生命周期 R0–R4

```text
R0 需求评审 → R1 开发实现 → R2 测试验证 → R3 发布上线 → R4 运行复盘
      │             │             │             │             │
      └─ G0 ────────┴─ G1 ────────┴─ G2 ────────┴─ G3 ────────┴─ G4
```

### R0 · 需求评审（G0）

| 项 | 要求 |
|---|---|
| 输入 | 教师重点/大纲、教材范围、出题蓝图、目标批次、旧版差异说明 |
| 活动 | 明确范围/非目标、验收标准、风险、产物形态、是否需要 KC/评分卡/学习价值层 |
| 产物 | `试点项目实施计划.md` 或批次需求单；风险登记；验收标准 |
| 门禁 | `python scripts/quality_gate.py --stage r0 --batch {batchID} --mode advisory` |
| 通过 | 必需输入齐全；范围/验收/风险已写；用户确认 |
| 责任 | 用户 + MedMaster + 医学内容专家 |

**R0 红线：** 需求未确认不得进入 R1；不得用“先做再补需求”替代评审。

### R1 · 开发实现（G1）

| 项 | 要求 |
|---|---|
| 输入 | R0 确认的需求、教师重点、蓝图、既有脚本/契约 |
| 活动 | 建/改脚本、Schema、数据契约；冻结基线；单元测试；不修改源产物 |
| 产物 | 代码、Schema、`baseline_manifest.json`、单元测试、开发说明 |
| 门禁 | `python scripts/quality_gate.py --stage r1 --batch {batchID} --profile pilot --mode advisory` |
| 通过 | 基线 verify PASS；Schema 可解析；KC 注册表 check PASS；单测通过 |
| 责任 | AI 工程 + 医学内容（规则） |

**R1 红线：** 任何脚本不得写源题库/源复习资料；所有新产物落 `中间产物/` 或 `reports/`；源文件哈希冻结。

### R2 · 测试验证（G2）

| 项 | 要求 |
|---|---|
| 输入 | R1 产物、200 题学习价值报告、12 维评分卡、KC 映射、复习资料 MD |
| 活动 | 单元/集成/回归；KC 覆盖与孤儿检查；题目学习价值；文档评分卡；**详细度契约（HC-26）**；内容专家抽检 |
| 产物 | `kc_mapping_report.md`、`learning_value_*.json`、`review_scorecard_*.json/md`、`review_detail_*.json/md`、测试报告 |
| 门禁 | `python scripts/quality_gate.py --stage r2 --batch {batchID} --profile pilot --mode advisory` |
| 通过 | KC 200/200 主映射、125/125 重点覆盖、0 孤儿；item FAIL=0；评分卡 ≥3.5；关键维度 ≥3.5；详细度总分 ≥80% |
| 责任 | AI 工程 + 学习科学 + 医学内容 + 质量 |

**R2 红线：** 内容专家抽检不可省；自动指标不能替代人工 rubric；FAIL 必须回退修复，不能“记录后放行”。

### R3 · 发布上线（G3）

| 项 | 要求 |
|---|---|
| 输入 | R2 通过版本、评分卡、产物形态、站点数据 |
| 活动 | 形态门禁、站点一致性/链接、发布说明、回滚方案、签收 |
| 产物 | `quality_gate_*_r3_*.json/md`、发布说明、回滚清单、签收记录 |
| 门禁 | `python scripts/quality_gate.py --stage r3 --batch {batchID} --profile release_teacher_keypoint --mode enforce` |
| 通过 | 评分卡 ≥3.8；关键维度 ≥3.5；content_only ≤15%；anchor ≥80%；**详细度契约 PASS（掌握槽位 100%、卡片达标 ≥90%、自测答案 100%、模块八块 100%）**；形态/站点/链接全 PASS |
| 责任 | MedMaster + 质量 + 用户 |

**R3 红线：** enforce BLOCKED 禁止发布；不允许用 `--mode advisory` 绕过正式发布；发布前必须能回滚到上一版本。

### R4 · 运行复盘（G4）

| 项 | 要求 |
|---|---|
| 输入 | 线上版本、发布提交、学习数据/反馈 |
| 活动 | 线上最新性校验、健康检查、学习结果回收、问题归档、下一轮改进 |
| 产物 | `quality_gate_*_r4_*`、`pilot_analysis_*.md`、复盘记录 |
| 门禁 | `python scripts/quality_gate.py --stage r4 --batch {batchID} --commit {commit}` |
| 通过 | 线上指纹==本次提交；无 P0 回归；学习结果/反馈有记录；行动项进入下一轮 |
| 责任 | MedMaster + 学习科学 + 用户 |

**R4 红线：** 线上被更晚部署顶替视为发布失败；不能用旧内容覆盖线上更新版本；学习效果未验证不得对外宣称“提升”。

## 5. 例外、豁免与 SKIP

| 状态 | 含义 | 处理 |
|---|---|---|
| PASS | 满足阈值 | 进入下一阶段 |
| WARN | 不满足目标但未触及阻断线 | 记录原因、影响、补做计划；R2 可进 R3，但 R3 必须重新判定 |
| BLOCKED | 触及阻断线 | 禁止进入下一阶段；修复后重跑 |
| SKIPPED | 不适用/缺输入 | 必须写明原因；**不得当作 PASS**；R3 不接受关键项 SKIP |

**豁免规则：**

1. 只允许 WARN 豁免，不允许 BLOCKED 豁免。
2. 豁免必须写入 `reports/gate/*.md`：理由、影响范围、补做时间、责任人。
3. 同一问题连续两个版本 WARN → 自动升级为 BLOCKED（防止“永久警告”）。
4. 旧批次不追溯；新批次/新版本不得引用旧批次的豁免。

## 6. 版本化与变更管理

- **标准版本**：`policy_version` 语义化（major.minor.patch）。阈值/阻断线变化 → major；新增 WARN/检查项 → minor；文案/报告格式 → patch。
- **产物版本**：批次号 + 版本号（如 `batch041-v1`）；重新生成必须新版本，不得覆盖已签收版本。
- **旧产物**：只读冻结；不因标准升级回改；如需增强，另开批次或修订单。
- **变更流程**：提议 → 影响评估 → 更新 policy/规范/测试 → 跑 R1/R2 验证 → 用户确认 → 生效。
- **回滚**：policy 变更必须保留上一版 `quality_policy.json` 的 Git 历史；发布回滚以版本为单位。

## 7. 质量指标与复盘

**领先指标（每批必看）：**

- KC 主映射率、重点覆盖率、孤儿数、content_only 比例、provisional 比例
- item FAIL 数、逐项覆盖、错误认知覆盖、source exact、anchor verified
- 评分卡总分、关键维度、warnings/blocking 数
- 形态/站点/链接门禁结果

**滞后指标（试点/发布后）：**

- 1 周/4 周延迟测验、错题复现率、学习依从性
- 校考/执医相关分数、案例迁移正确率
- 认知负荷（NASA-TLX）、满意度、单位时间收益

**复盘节奏：** 每批 R4 一次；每季度一次标准审计；每年一次标准大版本评估。
