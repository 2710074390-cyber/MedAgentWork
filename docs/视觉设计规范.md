## 一、目标场景与受众

**这一步必须先做。** 不谈场景就谈"好看"，只会得到一堆互相冲突的偏好。

### 1.1 受众

| 维度 | 事实 | 设计含义 |
|---|---|---|
| 身份 | 医学生（考研 / 规培方向） | 术语密度高，不需要"科普感"的装饰 |
| 使用时长 | 单次连续阅读常超 40 分钟 | **正文可读性 > 信息密度**；字号取偏大值 |
| 使用姿势 | 屏幕 + 打印双轨 | 浅色为默认；深色为屏幕长读备选 |
| 核心任务 | 快速定位知识点 → 理解 → 记忆 → 自测 | 层级必须一眼可辨；检索靠目录树不靠滚动 |
| 设备 | 桌面为主，手机为辅 | 单栏优先；`--p-measure: 720px` 限制行宽 |

### 1.2 场景（三个，优先级递减）

| 场景 | 载体 | 首要目标 | 次要目标 |
|---|---|---|---|
| **在线长读** | `复习资料/*.html`、站端 mdToHtml | 层级清晰、久读不累 | 主题切换 |
| **交互自测** | `押题卷/*.html` | 作答状态一目了然 | 目录树导航 |
| **打印 / PDF** | 人工导出 | 灰阶可辨、不浪费墨 | 分页不切断卡片 |

> **打印场景的反向约束**：任何仅靠颜色区分的信息（如"已掌握/待巩固"）必须有文字或边框兜底，
> 否则打印成黑白后失效。这条约束直接决定了状态色必须成"fg + bg + border"三件套。

## 二、可复用的设计原则

按"违反后果的严重程度"排序，不是按美学偏好。

| # | 原则 | 判据（可检查） | 违反后果 |
|---|---|---|---|
| 1 | **单一事实来源** | 视觉常量只在一个文件定义 | 改一次要动 N 个文件，必然不一致 |
| 2 | **语义命名，不描述颜色** | 令牌名是 `--brand` 而非 `--blue` | 换配色时名字全错 |
| 3 | **层级完整** | h1–h6 全部定义 | 标题落浏览器默认，结构不可辨 |
| 4 | **尺度有限** | 字号 ≤8 档、圆角 ≤4 档、间距 8px 基准 | "随手取整"累积成视觉噪声 |
| 5 | **对比达标** | 正文对比度 ≥ 4.5:1 | 长读疲劳、打印看不清 |
| 6 | **状态不只用颜色** | 颜色 + 文字/边框冗余编码 | 黑白打印或色觉障碍下失效 |
| 7 | **动效有预算** | 时长 ≤ 300ms，只用于反馈 | 干扰阅读 |
| 8 | **零外部依赖** | 无 CDN / 无外部字体 | 项目硬约束（GFW 友好 + 单文件交付） |

### 关于原则 4 的量化依据

## 三、令牌体系（三层架构）

```
Layer 1  primitive   原始色阶/尺度    --p-blue-700 / --p-text-base / --p-space-4
   ↓ 只允许向下引用
Layer 2  semantic    语义角色         --brand / --fg-muted / --bg-elevated
   ↓
Layer 3  component   组件专用         --card-bg / --radius-card / --nav-h
```

**硬规则**：
- 组件样式**只允许引用 Layer 2**，特殊情况才用 Layer 3
- **禁止**组件直接引用 Layer 1（`background: var(--p-blue-700)` ✗）
- **禁止**任何硬编码色值（`background: #2563eb` ✗）

### 3.1 语义令牌清单（22 个）

| 组 | 令牌 | 用途 |
|---|---|---|
| 表面 | `--bg` `--bg-subtle` `--bg-elevated` `--bg-inset` `--bg-overlay` | 页面底 / 次级底 / 卡片 / 凹陷 / 遮罩 |
| 文字 | `--fg` `--fg-muted` `--fg-subtle` `--fg-on-brand` | 主 / 次要 / 弱化 / 反白 |
| 描边 | `--border` `--border-strong` | 常规 / 强调 |
| 品牌 | `--brand` `--brand-hover` `--brand-soft` | 主色 / 悬停 / 浅底 |
| 状态 | `--success` `--warning` `--danger` `--info` | 各配 `-bg` `-border` 三件套 |
| 领域 | `--tone-mastered` `--tone-familiar` `--tone-learning` `--tone-tip` | 复习资料掌握度 |

### 3.2 尺度

| 类型 | 档位 | 值 |
|---|---|---|
| 字号 | 8 | 12 / 13 / **14.5** / 16 / 18 / 22 / 28 / 34 |
| 行高 | 4 | 1.25（标题）/ 1.5（表格）/ **1.75**（正文）/ 1.9（导语） |
| 字重 | 4 | 400 / 500 / 600 / 700 |
| 间距 | 8 | 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 |
| 圆角 | 4 | 6 / 10 / 14 / 999 |

**正文 14.5px + 行高 1.75** 是这套尺度里最关键的取值：中文长文低于 14px 或行高低于 1.6，
40 分钟连续阅读的疲劳度显著上升。

## 四、视觉层级与配色

### 4.1 层级靠四件事，不是靠"加粗放大"

| 手段 | 强度 | 适用 |
|---|---|---|
| **尺度**（字号差） | 最强 | h1→h6 主层级 |
| **间距**（前后留白） | 强 | 分组、段落呼吸 |
| **字重** | 中 | 同级内的强调 |
| **颜色**（fg / muted / subtle） | 弱 | 元信息降级 |

实践中**间距最容易被忽略、性价比最高**：同样两段文字，段间距从 8px 提到 16px，
层级感立刻出现，且不改任何字号。

### 4.2 层级规则

- 相邻标题层级字号差 ≥ 1.2 倍（`14.5→18→22→28` 满足）
- 标题行高紧（1.25）、正文松（1.75）—— 对比本身就在表达层级
- 标题**上方留白 ≥ 下方留白 × 1.5**，视觉上才会"归组"到下面的内容
- 正文行宽 ≤ 720px（约 38–42 个中文字符）

### 4.3 配色规则

- 中性色用**冷调灰**（带蓝相），纯灰 `#888` 在暖屏上会发闷
- 品牌色取**中低饱和**蓝：医学场景要"冷静、可信"，高饱和蓝有促销感
- 状态色**必须三件套**（`fg` + `bg` + `border`），保证黑白打印可辨
- 深色模式**不是简单反色**：底色用 `#0a0a0a` 而非纯黑（纯黑与内容对比过强，
  反而加剧眼睛调节负担），文字用 `#e6e8eb` 而非纯白

## 五、可落地的实现方法

### 5.1 迁移映射表

现有 6 套命名 → 统一令牌。按此表可直接机械替换。

| 现有文件 | 现有令牌 | 统一为 |
|---|---|---|
| index.html | `--bg` `--bg-2` `--surface` | `--bg` `--bg-subtle` `--bg-elevated` |
| index.html | `--text` `--text-2` `--text-3` | `--fg` `--fg-muted` `--fg-subtle` |
| index.html | `--brand` `--deep-1/2/3` | `--brand` `--brand-hover` `--brand-soft` |
| index.html | `--ok` `--warn` `--err` | `--success` `--warning` `--danger` |
| quiz_template | `--bg-primary/secondary/tertiary` | `--bg` `--bg-subtle` `--bg-elevated` |
| quiz_template | `--text-primary/secondary/tertiary` | `--fg` `--fg-muted` `--fg-subtle` |
| quiz_template | `--accent` `--accent-light` | `--brand` `--brand-hover` |
| quiz_template | `--correct` `--wrong` `--picked` | `--success` `--danger` `--brand` |
| review_template / render_review.py | `--color-master/familiar/understand/warning/tip` | `--tone-mastered/familiar/learning/tip` |
| qbank | `--bg` `--card` `--ink` `--ink-soft` `--line` | `--bg` `--bg-elevated` `--fg` `--fg-muted` `--border` |
| build_html_final | *（无令牌）* | 全量套用 + 内联 `design-tokens.css` |

### 5.2 执行步骤

| 步骤 | 动作 | 验收 |
|---|---|---|
| 1 | 把 `design-tokens.css` 内联进各模板 `<style>` 最前面 | 令牌可解析 |
| 2 | 按映射表替换令牌名 | `check_visual.py` 覆盖率 ≥ 95% |
| 3 | 补齐 h1–h6 定义 | FAIL 归零 |
| 4 | 把非标字号/圆角吸附到最近档位 | 字号 ≤8 档、圆角 ≤4 档 |
| 5 | 补全深色主题缺的语义令牌 | 主题对称性检查通过 |
| 6 | 纳入发布门禁 | `check_visual.py --all --strict` 退出码 0 |

### 5.3 优先级（按 ROI 排序）

1. **补标题层级**（4 个文件）—— 改动最小，读者感知最强
2. **内联 tokens + 改 index.html**（覆盖 74%，是站端门面）
3. **quiz_template + review_template**（产物量最大）
4. **build_html_final**（从零开始，工作量最大但最彻底）

### 5.4 门禁接入

```bash
python scripts/check_visual.py --all            # 查看报告
python scripts/check_visual.py --all --strict   # WARN 也判失败（发布前）
```

建议在 `docs/产物格式规范.md` 第 5 节发布流程里，与 `verify_produce_rules.py` 并列执行。
