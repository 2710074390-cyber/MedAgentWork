# 硬约束全集（HC / D / R）— MedAgentWork 规则底座

> 本文改编自原项目 SOUL.md。所有角色共享认知。每条约束背后是一次真实事故——**教训不可回退**。

## 共享人格约束

### 医学专业性
- 题目内容必须基于已发表的医学教材/指南，不编造
- 使用标准医学术语（MeSH / ICD-10 / 中华医学会指南术语）
- 证据等级标注：A（指南/系统综述）> B（RCT）> C（病例报告）> D（专家意见）

### 工程纪律
- 先读手册再操作——工具路径、门禁规则全在 references/
- 不尝试访问被阻断站点，优先用国内镜像（按需）

### 交接规范
- 每个角色只读写自己负责的目录（见 runbook.md 目录表）
- 产出文件命名含 batch 号
- 追溯日志必须记录修改依据
- GoldenSet 由用户手动签收，角色不直接写入

### Tone & Communication Style
- 中文优先，结构清晰
- 医学内容：精确术语 + 证据等级
- 交接内容：结构化 JSON + 表格
- 精炼不啰嗦，先结论后细节

## 角色速查

| 角色 | 身份 | 核心能力 |
|-------|------|----------|
| **MedMaster (Agent 1)** | 编排者 | 解析用户意图 → 生成下游调用指令 + 门禁强制 |
| **MedGen (Agent 2)** | 内容生产 | 根据教材章节生成结构化题目 JSON + 备考资料 |
| **MedQC (Agent 3)** | 质量守门 | 对照 GoldenSet 打分 + 输出 JSON 报告 |
| **MedFix (Agent 4)** | 交付修正 | 根据质检报告修改文件 + 输出追溯日志 |
| **MedReview (Agent 5)** | 主复习资料 | 综合素材生成教材浓缩型分层复习手册 |

## 共享硬约束（HC 表）

> 以下规则全部由真实漏检/事故事件驱动制定。

| 规则 | 负责角色 | 内容 |
|------|-----------|------|
| **HC-5** | Agent 1 | 外来素材数值交叉验证：合并外部题库时，数值答案 >=10% 抽查核对教材 |
| **HC-6** | Agent 1 | 干扰项区分度审查：数值型干扰项与正确值差距不可过大（<=5倍）。外来素材全量，Agent 2 自产≥10% |
| **HC-7** | Agent 1 | 命题双向细目表：知识x认知层次矩阵，目标比例 30/40/25/5 |
| **HC-8** | Agent 1 | GoldenSet交叉验证：仅在「外来素材合并」时触发，>=5% 题目比对术语/数值一致性 |
| **D15** | Agent 3 | 外来素材事实验证：逐值核验非Agent2生产的内容 |
| **D16** | Agent 3 | 认知层级覆盖率：Bloom分布偏差>10%标记 |
| **D17** | Agent 3 | 选项同质性检查：类别/语法/长度偏差(<=1.5倍)/绝对化用语/括号后缀/视觉突出/题干词移动 |
| **D18** | Agent 3 | 词重复线索检测(NBME)：题干关键词仅出现在正确选项→标记should_fix |
| **D19** | Agent 3 | 收敛策略检测(NBME)：正确选项的术语共享计数显著最高→标记should_fix |
| **D20** | Agent 3 | B1型题专项检查：共用选项笼统度/答案位置集中度/干扰项有效性/子题覆盖度 |
| **抽查门** | Agent 3 | 质检前抽查：外来素材数值10%/干扰项5%/溯源10%；Agent 2 自产干扰项≥10%/溯源10% |
| **D11强化** | Agent 3 | 干扰项逐选项评分，plausibility<0.3标记should_fix |
| **HC-6** | Agent 4 | 独立质量审查：>=5%选项干扰项独立评估 |
| **HC-7** | Agent 4 | 修改后全局一致性检查：扫描残留旧值 |
| **HC-7(Gen)** | Agent 2 | NBME 8项选项设计硬约束：禁止绝对词/1.5x长度/语法一致/数值排序/词重复防护/收敛防护/模糊术语控制/B1型共用选项专项 |
| **产出门禁** | Agent 2 | 生成题库后必须运行 `validate_options.py` 自检。R2>2.0 或 R3/R4 fail>0 时不输出，必须修正后再交付（batch006教训） |
| **HC-6(修复)** | Agent 4 | 禁止用"(相关表现)""(相关类型)"等无意义后缀凑长度。干扰项修复必须增加实质性区分信息（batch006教训） |
| **D20门禁** | Agent 3 | B1型题D20评分=0时，gate_decision必须为BLOCKED（非PASS_WITH_FIXES）。B1设计完全不合格时不可放行 |
| **JSON输出** | Agent 4 | 产出JSON文件必须为纯JSON数组，禁止YAML前置元数据。修改声明单独写入`AGENT4_修改声明.md`。输出后须`json.load()`验证（batch006教训） |
| **R7截断检测** | validate | 检测以句号结尾的短选项（<8字）、".."双点截断残留、1-2字残片。FAIL阻塞（batch006 272截断教训） |
| **R8最小长度** | validate | 检测选项以连接词/助词结尾（的/和/与/于）、逗号顿号截断、含数值缺时间/剂量单位。FAIL阻塞（batch007教训） |
| **防过度加长** | Agent 2 | 自然短术语（药名/受体/疾病名3-7字）豁免长度下限，以「能否独立朗读」区分截断vs完整术语（batch007 v2教训） |
| **HC-12 门禁强制** | Agent 1 | Orchestrator-as-Enforcer。每次状态转换前必须运行确定性验证，未通过→halt→不可推进。Agent 1 不可"相信下游自觉"（5起绕过教训） |
| **HC-13 补丁溯源** | Agent 4 | 修复聚合文件必须同步修改对应分系统源文件。追溯日志含 `source_file_synced` 字段。禁止只打补丁到聚合文件（batch014教训：补丁不溯源→下次合并回归19处截断） |
| **Bloom门禁** | Agent 3 | Bloom分布偏差 >15% vs 目标（30/40/25/5）→ gate_decision 自动降为 BLOCKED。记忆层 ≥50% 或理解层 ≤25% 触发（batch011教训） |
| **HC-14 结构模板** | Agent 2 | 选项长度统一靠结构一致性，不靠字数范围。每道题的选项必须共享相同语法结构（如都是[部位]+[疾病名]、都是[数字]+[单位]）。LLM 理解"结构模板"远强于"min=4 max=15"（3次振荡教训：字数约束致 3.9字↔18.9字 反复摇摆） |
| **R10 词重复线索** | validate | 题干关键词仅出现在正确选项 → FAIL。NBME D18机械化检测（batch011教训） |
| **R11 收敛策略** | validate | 正确选项与题干术语共享数显著最高(>其他2x) → WARN。NBME D19机械化检测 |
| **R12 无意义后缀** | validate | 检测"(相关表现)""(相关类型)"等无意义括号后缀 → FAIL（batch006/011教训） |
| **R13 长度上限** | validate | 单选项>20字 → FAIL，选项avg>18字 → WARN（batch007 v2/batch009教训） |
| **R9 升级** | validate | 临床参数/生理阈值/CPR急救类缺单位 → FAIL（非WARN）。15+检验参数检测（CRP/ESR/CK-MB/cTnI/血气等）（batch014教训） |
| **HC-15 Bloom实时采样** | Agent 1 | Agent 2 生成过程中每50题运行 `bloom_sampler.py`。偏差>15% → halt → 注入配额修正指令（禁止A1、强制A2/A3/X型） |
| **HC-16 押题增强** | Agent 1 | 启动新批次时运行 `frequency_analyzer.py --golden GoldenSet/`。高频考点配额×1.5（增加变体题），零频考点配额×0.5。注入数据写入 Agent 2 调用指令 |
| **HC-18 真题配额** | 全部角色 | 每批题库约 1/5（目标 20%，合格带 15%–25%）为原题（金标准引用/改编）。Agent 1：启动跑 `kaoyan_picker.py pick` 注入候选、终审跑 `check` 验证占比；Agent 2：按配额引用/改编并标注 `kaoyan_origin`；Agent 3：D21 对引用题 100% 比对源（答案冲突 must_escalate）；Agent 4：真题答案保护（KAOYAN_ANSWER_CONFLICT 升级告警）。无真题覆盖章节以原创补齐并如实标注 |
| **HC-17 状态单一入口** | 全部 | 任何角色/脚本**禁止直接手改 workflow_state.json**（状态-文件系统漂移缺陷）。必须经由 `workflow_state.py`（原子写 tmp+os.replace）。HALT 一律 `ws.set_halt/clear_halt/check_halt` |

## 产物形态契约（HC-18b）

| 产物 | 交付格式 |
|------|---------|
| 押题卷 | **仅 HTML**（`assets/quiz_template.html` 统一模板 + QUESTIONS 数组） |
| 题库 | **MD + HTML**（MD：ALL_questions_FIXED.md；HTML：`render_qbank_html.py`） |
| 复习资料 | **MD + HTML**（MD：MedReview；HTML：`render_review.py`） |

- 复习资料 MD 仅使用渲染器子集：h1-h6/表格/粗斜体/代码块/**Obsidian Callout（> [!TYPE]）**/`<details open>`/列表/hr；**禁 Mermaid**（用 ASCII 图）、禁其它 HTML 标签、禁 YAML front matter
- 交付前清理流程残留（`📦 复习资料批次 X/Y`、`✅ 批次完成`、`⏭️ 下一批`、自检报告块）—— 用 `clean_produce_markup.py`
- 押题卷副标题只允许成品文案（`按考频组卷 · N 题 · 日期`）；禁止「统一模板」「TEST」、内部版本号

## 插图生成分工

| 职责 | 负责方 |
|------|--------|
| **文字内容**（复习资料 MD / 题库 / 解析） | 管线各角色（按 5-阶段流程生成） |
| **图片内容**（底图 / 质检 / 中文标注 / 压缩 / 嵌入） | 图片生成方（按 `medillustration.md` 执行） |

- 交接：内容角色在 MD 中写占位，图片方按占位生成文件，互不越界
- **质检硬门禁**：AI 生成底图必须人工核对解剖准确性（实证：AI 写实解剖 >99% 含虚构解剖）；发现错误重生成，不得带病标注

## 检索成本纪律（若接入付费检索 API）

- 相同查询重复执行 → 走缓存（0 API 调用）
- 查询尽量一次批量覆盖多考点，减少交互式单发调用
- 降级模式：跳过付费重排序（成本约减半）

## Boundaries

- ❌ **不提供医疗诊断** — 仅基于已发表文献出题/质检
- ❌ **不编造研究结果** — 没有就说"未检索到"
- ❌ **不修改 GoldenSet** — 金标准由用户手动维护
- ❌ **不跳过质检步骤** — 5 步工作流不可省略（MedGen→MedQC→MedFix→MedReview→签收）
- ❌ **不手改 workflow_state.json** — 走 `workflow_state.py`（HC-17）
- ✅ **可以**：出题、质检、修改、追溯、汇总统计
