**第一句**：两个模块的技术密度远超同类个人项目，真正具备"非显而易见"特征的创新点有且仅有三处，且全部集中在"如何让大模型的生成结果可被机械验证"这一条主线上，而不是"如何用大模型出题"。

### 1.2 评估方法

采用四步法：

**第一步，技术分解**。逐模块阅读源码与设计文档，把系统拆解为可独立主张的技术点，每个技术点记录四项要素：所解决的技术问题、所采用的技术手段、与现有技术的差异、在代码中的可核查位置。不以 README 的宣传语为依据，只以代码实现与测试为准。

**第二步，三性判断**。对每个技术点分别判断新颖性（是否被单篇文献完整披露）、创造性（对本领域技术人员是否显而易见）、实用性（能否重复实施并产生技术效果）。

**第三步，现有技术比对**。以中英文双语检索中国、美国、欧洲专利库，锁定最接近的对比文件，逐件比对技术特征差异。

**第四步，路径设计**。在给定约束下（已公开的事实、剩余时间窗、预算量级、维权可行性）设计从技术挖掘到申请节奏的全链路方案，并对每一处可能出问题的环节预设应对。

## 第二部分 项目技术画像

理解专利价值的前提是理解系统实际做了什么。本部分不引用项目对外宣传的表述，只依据代码实现与测试，把两个模块拆解到可独立主张的技术单元。

### 2.1 两个模块的定位差异

两者不是同一产品的两个版本，而是同一方法论的两种交付形态，其技术重心完全不同。

MedAgentWork 是**生产侧**。它假设使用者是一个教研团队，愿意配置金标准、维护硬约束库、按批次跑门禁。它的技术价值在于"如何把不确定的模型输出压进确定的产物契约"，因此重心是**门禁与契约**。

MedKit 是**消费侧**。它假设使用者是一个学生，只有一台笔记本和一个 API Key。它的技术价值在于"如何在没有服务器、没有标注数据、没有运维的前提下，让个性化学习闭环跑起来"，因此重心是**本地数据主权与轻量推断**。

这个差异决定了：MedAgentWork 的创新点集中在**校验**，MedKit 的创新点集中在**存储与状态**。

### 2.2 MedAgentWork 技术架构

系统按"五阶段接力 + 阶段门禁"组织。阶段之间不是函数调用，而是**文件契约**：上游只能写自己负责的目录，下游只能读上游产物，每次阶段转换必须由确定性脚本裁决放行或阻断。

```
启动登记 → 出题 → 门禁A2 → 质检 → 门禁A3 → 修复 → 门禁A4
→ 成册 → 门禁A5 → 终审 → 人工签收 → 归档
```

三层治理结构：

**第一层，产物契约**。7 份 JSON Schema 定义每个阶段的输入输出形状，摄入即校验。契约不只是字段名，还包括条件必填（例如题目版本 2.1 起 `concepts` 数组必填）、取值范围、跨字段一致性。

**第二层，确定性门禁**。约 120 个脚本承担实际裁决，全部零第三方依赖、纯标准库、可离线运行。门禁结论是四态而非二态：PASS、WARN、BLOCKED、SKIPPED，并明确规定 **SKIPPED 不等于 PASS**——未执行的检查不得被计为通过。

**第三层，阈值单一事实来源**。所有可调阈值集中在 `quality_policy.json` 与 `pipeline.yaml` 两处，按 profile 分档（试点档与发布档阈值不同），改配置即全局生效，避免"声明与实现双轨"。

### 2.3 MedKit 技术架构

按"生成链 + 学习内核"双轨组织。生成链是可选的（默认关闭，需在设置中开启），学习内核是常驻的。

生成链：教材解析 → 分片 → 出题 → 质检修复 → 门禁 → 组卷 → 产物落盘。带断点续跑、逐题审核台、单题重掷、成本预估与实际用量记账。

学习内核四层：

**题库域**。三张表（题库、题目、作答流水），作答走 append-only 流水，判分口径与导出的押题卷同源（集合比较，`"B D"` 等价 `"BD"`），避免"网页判对、导出判错"。

**错题文件域**。错题以 Markdown 文件为真身，一道错题一个文件，front matter 承载可查询字段，正文承载可阅读内容，字段全可空。SQLite 在本域降级为**可弃索引**，删除后全量重建可得逐行相等的结果。

**知识图谱域**。题目通过稳定哈希绑定到知识点主键，形成多对多映射；映射采用三段式（精确匹配自动确认、模糊匹配必须人工确认、模型兜底降级为规则并如实说明）；学习者状态用四参数知识追踪模型加经验贝叶斯收缩估计，且该状态是**读模型**而非真相，可从作答流水重放重建。

**调度域**。复习间隔由 FSRS 算法排程，SM-2 作为兼容实现保留，两套算法的状态字段并存于同一记录，切换算法时按语义映射播种，保证"连续记住两次即已掌握"这条对用户的承诺不因换算法而改变。

## 第三部分 核心技术点与创新点梳理

在两万余行代码中，真正具备「非显而易见」特征的可能只有三处。本部分先逐一列举技术点，再做一次收敛，把「工程上做得好」与「法律上可主张」区分开。

### 3.1 MedAgentWork 技术点清单

**T1 阶段门禁状态机**

技术问题：多阶段模型管线的中间产物质量不可控，任一阶段产出劣化会沿链路放大，而人工无法逐阶段复核。

技术手段：每个阶段转换绑定一个确定性脚本作为唯一放行条件；门禁返回四态结论；BLOCKED 触发 HALT 标志，管线停止并强制回退到对应角色，清除 HALT 必须显式调用专用命令；SKIPPED 在报告中与 PASS 严格区分。

与现有技术差异：现有 LLM 管线多用"模型自评 + 人工抽检"，本方案把裁决权完全移出模型，且用状态机保证"不可跳过"。

代码位置：`gate_check.py`（约 2000 行）、`quality_gate.py`、`quality_policy.json`。

**T2 选项设计机械化校验**

技术问题：模型生成的干扰项存在系统性形式缺陷（正确项显著更长、数值缺单位、选项被截断为半句、否定词未标注），这些缺陷会直接泄漏答案或使题目不可作答。

技术手段：13 条纯文本规则 + 1 条结构规则，全部基于产物本体的字符串与数值计算，不调用任何模型。代表性规则包括：正确项与最短干扰项的长度比双阈值（超 2.0 判失败、超 1.5 判警告）；数值选项的取值范围与均值之比低于 0.1 判定为区分度不足；临床参数（如左室射血分数、脑钠肽、用力呼气容积）后的数值缺少单位直接判为事实错误；选项以句末虚词或逗号结尾判定为截断。

与现有技术差异：把"什么样的选项是坏选项"从主观判断转为可枚举的机械特征，并对每条规则设计正负样本以验证规则确实会触发。

代码位置：`scripts/validate/rules_numeric.py`、`rules_structural.py`、`rules_static.py`。

**T3 认知分层独立重算**

技术问题：质检报告中的认知层级分布是模型自述数据，模型会给出"看起来合理"的分布以通过检查。

技术手段：门禁不采信自述值，而是从题库产物本体重新计算认知层级分布，与自述值交叉比对，偏差超过 5% 即阻断。子门禁独立编号，报告中分别记录"自述偏差"与"重算偏差"两项。

与现有技术差异：多数方案止步于"要求模型输出分布并检查是否落在目标区间"，本方案增加了一层"自述数据不可信"的对抗性设计。

代码位置：`gate_check.py` 的 `GATE-A3-BLOOM` 与 `GATE-A3-BLOOM-RECOMPUTE` 子门禁。

**T4 页码反查**

技术问题：题目声称来源于教材某页，但该页码可能是模型编造或超出教材范围。

技术手段：以教材分块索引中真实存在的页码集合为基准，对题目声明的来源页码做三级判定——页码为 0 视为占位符直接失败、页码超过索引最大页直接失败、页码不在索引中记为警告；来源非教材页码（如指南年份）单独归类为"无法反查"而非失败，避免误伤。

代码位置：`scripts/fact_check.py` 的 `check_pages`。

**T5 金标准交叉验证的双阈值设计**

技术问题：新题与既有真题可能重复，或术语相似但关键数值冲突；但金标准语料的题干是"题号 + 选项 + 多子题打包块"的混合结构，直接做相似度会产生大量误报。

技术手段：采用包含度（交集除以较短集合大小）与杰卡德系数双指标，而非单一余弦或杰卡德。判定阈值经实测校准：包含度不低于 0.85 且交集词数不少于 4 判为疑似重复；包含度不低于 0.55 且双方数值元组各不少于 2 个且交集为空判为数值冲突；其余相似项降级为参考。数值提取只取正确选项与解析，刻意排除干扰项数值，避免"干扰项撞车导致必然有交集"的假阴性。

与现有技术差异：这不是通用相似度算法，而是针对"打包块式语料"这一特定结构的校准结果，阈值组合本身携带了数据结构知识。

代码位置：`scripts/fact_check.py` 的 `golden_crosscheck`。

**T6 教师重点锚点覆盖与落点行核验**

技术问题：上游的教师重点原文是权威范围契约，但下游复习资料在"概括"这一步会丢失数值、时间窗、分级界值等硬事实，且这种丢失在通读时极难发现。

技术手段：三步。第一步，从教师重点原文中提取带单位的硬事实集合，归一化处理全角数字、异体罗马数字、单位别名（厘米与 cm、分钟与分）、分隔符（波浪号与"至"与"到"）以及数字与单位之间的空格。第二步，要求复习资料为每个编号条目设置结构化落点行，格式固定为"重点原文（第 N 条）：照录原文关键句"。第三步，也是关键一步，硬事实必须在**该条目的落点行内部**出现，而不是在文档任意位置出现即算通过——这一局部性约束专门用于堵住"别处命中导致的假通过"。匹配时使用词边界断言，防止"2 周"被"12 周"命中。

代码位置：`scripts/check_keypoint_coverage.py` 的 `drop_lines` 与 `partial` 判定。

**T7 生成期概念标注与概念图构建**

技术问题：知识点与题目的映射若在事后用文本相似度推断，在"一题一锚点"的题库上多标签率封顶约 5%，且不可复核、不可追溯。

技术手段：把映射前移为生成契约。要求生成时输出概念数组，每条含角色（主概念、鉴别概念、关联概念）、所属重点条号、概念名、以及不少于 8 字的判定依据；约束恰好一条主概念且其条号必须等于本题声明的锚点条号；不同题型的最少概念数不同（病例组题与多选题不少于 2 条）。落盘前由零依赖校验脚本做六项检查。下游建图时优先解析声明式标注，无声明才回退推断，两类来源在产物中显式区分。

代码位置：`schemas/agent2_output.schema.json`、`scripts/check_source_concepts.py`、`scripts/label_concepts.py`、`scripts/build_concept_graph.py`。

**T8 组卷公式**

技术问题：从题库抽题组卷需要同时满足考频覆盖、难度区间、题型配比、答案位置均衡四项约束。

技术手段：权重等于考频权重乘以难度配平系数，先做硬过滤（无功能干扰项数量超限的题不入卷、难度校准冲突未处置的题不入卷），再做置信度加权（高可信 1.0、中 0.7、低 0.4），再做题型配额，最后用贪心纠偏做答案位置均衡（目标每个选项位置不超过 25% 加 5 个百分点）与卷面平均难度配平（目标区间 0.55 至 0.65，迭代 40 轮）。

代码位置：`scripts/paper_builder.py`。

**T9 难度锚点外部校准**

技术问题：本地题库没有作答数据，无法估计题目难度。

技术手段：用公开数据集的人工标注锚点，配合先验表，做外部先验估计，并在产物中显式标注"这是先验估计而非实测难度"，禁止对外宣称实测。同时定义冲突处置分流（保留先验、保留锚点、标记待修、不确定），不同处置对应不同的入卷策略。

代码位置：`scripts/anchor_bank.py`、`apply_calibrated_difficulty.py`。

**T10 扫描册按版式分流解析**

技术问题：历年真题扫描件有单栏与双栏两种版式，单一 OCR 通道无法同时处理。

技术手段：按版式分流——单栏册走本地 OCR 并并行分页，双栏册走版面重建服务。两者不可互换：版面重建服务会吞掉单栏册的答案行，本地 OCR 会把双栏页左右栏并成一行。此外定义了共用备选答案题组的选项绑定、病例组题号重排的顺序配对、以及"选项加下一题题号"并段的切分规则。

代码位置：`scripts/zhiyi_pdf_ocr.py`、`zhiyi_pdf_mineru.py`、`zhiyi_pdf_parse.py`。

**T11 学科个性化检索**

技术问题：不同医学学科的文本结构差异极大（方剂组成不能切断、影像描述需要保留上下文），统一分块与统一检索参数会显著降低召回质量。

技术手段：逐学科配置分块大小、召回数量、混合检索开关、关键词权重、语义保护规则；检索采用两阶段（向量与关键词混合打分后重排，再经重排模型筛选），并在成本受限时降级跳过重排阶段。

代码位置：`知识库素材/configs/`、`search_kb.py`。

### 3.2 MedKit 技术点清单

**K1 生成链编排**：断点续跑（检查点记录已完成分片与已生成题目）、取消传播（取消事件穿透到模型客户端，立刻截断流式响应）、分片摘要压缩、成本预估与实际用量记账、逐题审核台（剔除、行内编辑、单题重掷）。属常规工程组合。

**K2 四类确定性门禁**：选项质量、认知分层、数值一致性、溯源完整性、去重。移植自 MedAgentWork 的规则子集。

**K3 题库域与导入往返一致**：以"自己导出的 Markdown 必须能原样导回来"作为零成本正确性判据；解析器带版本号，解析逻辑改进后可对已入库题库一键重解析，避免"代码修好了但历史数据仍是脏的"。

**K4 文件为真身、索引可弃**：错题以 Markdown 文件为唯一真相，SQLite 索引按内容哈希三态增量重建（新增、内容变更重解析、内容未变跳过、索引有而文件已删则删行），删除索引后全量重建结果与重建前逐行相等。判据用内容哈希而非修改时间，因为同步盘会改时间戳但内容未变。写入走临时文件加原子替换；单文件解析失败只记警告，绝不回写用户文件。

**K5 知识身份绑定与学习者模型**：题目绑定到稳定哈希主键；映射三段式（精确匹配自动确认、模糊匹配必须人工确认、模型通道未实现则降级并如实说明）；掌握度用四参数知识追踪模型估计，并用经验贝叶斯收缩把单次观测拉回人群先验（先验 0.30、等效观测数 2），使第一次作答不产生极端值，观测数达 8 次后先验权重降至两成；状态表为读模型，可从作答流水重放。

**K6 调度算法无损切换**：FSRS 为默认、SM-2 为兼容实现，两套状态字段并存；切换时按语义映射播种（间隔映射为稳定性、难度因子映射为难度），避免刚复习完的卡片被当作全新卡；参数经实测重标定（学习步长由秒改为分钟、最大间隔由 36500 天降为 180 天、关闭随机抖动以保证同输入同输出）。

**K7 模型能力三层解析**：上游字段优先（服务商自报的输入模态）、内置目录次之、命名启发式兜底；关键在于缺失时返回"未知"而非"不支持"，以区分"确定不支持"与"没拿到字段、请继续往下一层找"。

**K8 错题助手四条可证伪硬约束**：结论必须带可解析的来源定位；检索不到依据必须回答不知道，禁止用通识补全；必须回应用户自己写下的理解与疑问；工具失败必须显性报告。编造的引用路径在校验层被剔除并回报剔除清单。编排不依赖各家服务商参差的函数调用能力，而让模型输出受限 JSON 动作，流式时对 JSON 做增量部分解析。

**K9 题库同步**：按文件内容哈希记录同步状态，远端未变且本地仍在则不发起任何请求；变更才下载并按更新策略合并，同题保留原标识，保证作答流水、收藏、笔记不丢；适配层保真搬运题型、认知层级、考点、教材页码、真题出处与年份等通用导入会丢失的字段；多个来源独立成败，单源失败不影响其余；限流后停止逐份重试。

**K10 切片与配额**：按 token 预算切片、按题型与认知层级配额分配、超发截断。

### 3.3 创新点提炼：三处真正的"非显而易见"

把 21 个技术点做一次收敛，只有三处同时满足"解决了他人未识别的技术问题""采用了非显而易见的技术手段""产生了可量化且非预期的技术效果"。

**I-1 生成期知识身份绑定**

现有做法是把映射放在生成之后：先出题，再用文本相似度或向量检索把题挂到知识点上。这条路线有一个结构性缺陷——挂错了无法复核，因为推断过程没有留下可验证的依据；而挂错比不挂更糟，会把掌握度归到错误的知识点上。

本方案把映射前移进生成契约：题目在被生成的那一刻就必须声明它测到哪几个概念、每个概念属于哪条重点、判定的依据是什么，并且主概念必须与本题声明的锚点条号一致。这不是"多写一个字段"，而是改变了数据的产生方式——映射从"事后推断的结论"变成了"生成时受约束的输入"，因而具备了三个性质：可审计（每条映射带依据）、可复现（受 Schema 版本约束）、可机械校验（零依赖脚本六项检查）。

可量化效果：同一套系统下，采用事后推断的学科其病例组题多标签率仅 4.9%，采用生成期声明并通过同锚点共属扩展的学科达到 55%；源标注解析成功率在门禁约束下维持在 98% 以上。

**I-2 证据局部性约束**

现有 RAG 引用校验多在文档级或段落级做相似度比对，判定"这段话在文档里找得到相似内容"。这挡不住一种失效模式：断言 A 的证据其实在文档另一处，两句话各自都真实，但组合起来是错的。

本方案要求证据必须与断言处于同一个结构化单元内：生成时输出"断言、证据定位、证据原文"三元组，校验时按定位取出该单元，在单元内部做归一化匹配，不匹配则整单元拒绝，而不是整篇文档拒绝。拒绝粒度从文档降到单元，是这处创新的实质。

可量化效果：在某学科 132 条教师重点的实测中，仅做全文级硬事实覆盖会出现"别处命中即通过"的假通过；加入落点行局部性约束后，可检出 30 条重点条目中硬事实未在落点行照录的情形，占全部条目的 22.7%。

**I-3 自述元数据独立重算**

生成模型对自身产物的属性描述（认知层级分布、难度、覆盖率）系统性地偏向"看起来合格"。多数方案的处理方式是提高阈值或增加模型投票，但两者都还在"让模型判断模型"的闭环里。

本方案把自述值降级为"待验证的输入"：校验器从产物本体重算同一指标，与自述值比对，偏差超阈值即阻断，且阻断是状态机级的——不可跳过、必须回退重新生成。这处创新的关键在于**把模型从裁判席移到被告席**，并为此设计了独立的子门禁编号与双指标报告。

可量化效果：该机制上线后，认知分层偏差从"自述层看似合规"变为"重算层可检出"，并暴露出一批此前被自述数据掩盖的分布漂移。

## 第四部分 可专利性分析

这是本报告的核心，也是最需要冷静的部分。技术判断可以讨论，但公开披露的日期是既成事实，法律对既成事实没有商量余地。

### 4.1 法律基线

**客体适格**。中国专利法第 25 条第一款第二项排除"智力活动的规则和方法"。软件相关发明要获得保护，必须构成技术方案：解决技术问题、采用技术手段、获得技术效果。审查实践中，单纯的算法或单纯的商业规则不予保护，但"算法特征与技术特征功能上彼此支持、存在相互作用关系"的整体方案可以保护。这意味着权利要求不能写成"一种出题方法"，而必须写成"一种由处理器执行、通过对生成结果施加结构化约束以降低校验开销的数据处理方法"。

**新颖性**。要求不属于现有技术，且没有任何单位或个人就同样的发明在申请日以前向专利局提出过申请并记载在申请日以后公布的申请文件中。现有技术指申请日以前在国内外为公众所知的技术——**公开即构成现有技术，不限地域、不限语言、不限形式**。GitHub 公开仓库、公开 Release、公开分发的技能包，全部属于"为公众所知"。

**创造性**。要求与现有技术相比具有突出的实质性特点和显著进步。对本领域技术人员而言非显而易见。中国实践中对"算法加技术特征"的组合，重点看算法特征是否与技术特征功能上彼此支持、是否解决了技术问题。

**宽限期**。中国专利法第 24 条规定，申请专利的发明创造在申请日以前六个月内，有下列情形之一的，不丧失新颖性：在国家出现紧急状态或者非常情况时，为公共利益目的首次公开的；在中国政府主办或者承认的国际展览会上首次展出的；在规定的学术会议或者技术会议上首次发表的；他人未经申请人同意而泄露其内容的。

**GitHub 公开不属于上述任何一种**。它不是政府主办或承认的国际展览会，不是规定的学术会议或技术会议，也不是他人未经同意泄露。因此，六个月宽限期在本案不适用。

**欧洲**。EPO 对新颖性采取绝对严格标准，欧洲专利公约第 55 条仅承认两种例外（滥用、符合 1928 年国际展览会公约的官方展览），**没有一般性宽限期**。发明人自己的任何公开都构成现有技术。

**美国**。35 U.S.C. § 102(b)(1)(A) 规定，在有效申请日之前一年或以内，由发明人或共同发明人本人，或由从发明人处直接或间接获得该主题的他人所作的公开，不构成 § 102(a)(1) 下的现有技术。**这是本案唯一仍然可用的宽限期通道**。

### 4.4 MedAgentWork 结论

这个模块的技术价值被严重低估，但专利价值被公开时点摧毁。

客观地说，它解决的问题是真实且被同行忽视的：整个行业都在讨论"怎么让大模型出更好的题"，而它讨论的是"怎么证明这道题是好的"——后者才是能形成壁垒的部分。T3 的"自述数据不可信"、T5 的"针对打包块语料的双阈值校准"、T6 的"落点行局部性约束"，三处都体现了对失效模式的深刻识别，而不是对流行技术的跟随。

但专利制度不奖励"事后看起来深刻"，只奖励"申请日之前未公开"。2026 年 9 月 11 日把全部门禁脚本以技能包形式公开发布，在法律上等同于把这套机制免费贡献给现有技术库。

因此：**以中国为目标的申请，不建议提交**。提交的结果大概率是被自身公开文献打掉，损失申请费与代理费，且公开的申请文件会进一步固化现有技术地位。

### 4.5 MedKit 结论

这个模块的工程完成度极高（1288 项测试、21 个版本、完整迁移与回滚设计），但发明高度不足。

原因是它的大部分技术选择都是"在已知选项中做正确取舍"，而不是"提出新的技术手段"。例如选择四参数知识追踪而非深度知识追踪，理由是单用户本地样本量永远达不到深度模型的需求——这是正确的工程判断，但判断本身不构成发明；选择内容哈希而非修改时间作为索引判据，理由是同步盘会改时间戳——这同样是正确判断，但内容寻址本身是版本控制系统的公知基础。

最具技术含量的是 K6 的跨算法状态播种与 K5 的"状态表为读模型"设计，但前者建立在已公开发表的 FSRS 算法之上，后者是事件溯源模式的常规应用。

因此：**MedKit 不宜作为专利布局的主体**。它的价值在产品质量与用户体验，应通过著作权、商标、以及"数据不出本机"的隐私承诺建立差异化。

### 4.6 客体适格性风险

即便转战美国，仍有两道关口。

**第一道，§ 101 适格性**。美国最高法院 Alice 案确立的两步法：先判断权利要求是否指向抽象概念，若是，再判断是否包含"显著多于"该抽象概念的创造性概念。软件类权利要求若写成"用通用计算机实现某规则"，几乎必被驳回。应对方式是把权利要求锚定在具体的**数据结构改进**与**系统状态迁移**上，而不是"出题"这个业务目标。例如主张"一种生成带结构化证据三元组的题目记录的方法，该记录使校验器可在单元级而非文档级完成一致性判定，从而将校验复杂度由文档长度线性降为单元长度常数"——这里的技术效果是可测量的计算复杂度改进，而不是教学效果。

**第二道，显而易见性组合**。审查员会把"生成模型 + 校验规则 + 质量门禁"三篇文献组合起来，主张显而易见。应对方式是证明存在**教导远离**（teaching away）：现有技术普遍认为质量判定应由模型或专家完成，而本方案明确主张"模型自检不可信、必须由确定性脚本裁决"，这与主流教导方向相反，且有实测数据支撑（模型自述的认知分层分布与实际重算分布偏差超过阈值即阻断）。

## 第六部分 全链路方案

前面几部分说明了「能做什么」与「还剩多少空间」，本部分给出可执行的动作序列。每一步都标注了时点、交付物与硬约束。

### 6.1 阶段零：止血与冻结（本周内）

这一步优先级最高，因为它决定后面所有动作是否还有意义。

**动作一，停止机制层公开**。把 MedKit 主仓与 medagentwork-skill 子模块转为私有，或在保持公开的前提下停止推送任何涉及机制改进的提交。若必须保持开源（AGPL 承诺、社区依赖），则建立"公开版"与"开发版"双轨：公开版只接收缺陷修复与文档改进，机制演进在私有分支进行，直到申请日之后再合并。

**动作二，建立未公开增量清单**。把当前工作树中尚未提交的改动逐项登记：文件路径、改动内容、技术效果、是否已在别处披露。这是未来唯一可以主张新颖性的弹药库。当前已知的候选只有 MedKit 的一处调度重接线提交，需要立即评估是否值得为此单独布局。

**动作三，证据固化**。对两个仓库执行完整的历史导出与哈希存证：导出全部提交记录与关键文件在各时间点的内容哈希，生成一份带时间戳的清单，交由第三方时间戳服务或公证处固化。这份证据有两个用途——将来主张美国宽限期时需要证明"公开由发明人本人作出"；若转向防御性公开策略，需要证明"该技术已于某日进入公有领域"。

**动作四，权属核查**。确认开发过程中是否使用了学校实验室资源、导师课题经费、或受雇期间完成。若构成职务发明，申请权归属单位，个人申请会埋下权属瑕疵。这一项应在投入任何申请费用之前完成。

### 6.2 技术挖掘（第 1 至 2 周）

目标不是"把已有技术点包装成专利"，而是**设计出尚未公开的下一代机制**。已公开的内容在法律上已经无法挽回，唯一有价值的动作是向前看。

建议围绕一条主线做挖掘：**从"生成后校验"走向"生成时不可伪造"**。当前的机制本质上是"生成完再查"，下一代应该是"生成时就无法产生不可验证的产物"。

三个具体方向：

**方向一，把证据局部性约束做成通用中间表示**。当前只在教师重点覆盖这一处实现（落点行内硬事实核验）。可以扩展为一种产物级的不变量：任何断言在写入产物时必须携带一个可机械解析的定位符与一段原文片段，产物在结构上不允许存在"无定位的断言"。这样校验从"事后比对"变成"结构上不可能违规"。这个方向的技术效果可以量化：校验复杂度从与文档长度相关降为与单元数相关，且违规产物在写入阶段即被拒绝，不需要全量回扫。

**方向二，把自述元数据的重算扩展到多维并定义偏差传导**。当前只对认知分层做了重算。可以扩展到难度分布、考点覆盖、去重率，并建立"上游偏差如何在下游累积"的传导模型，据此决定在哪个阶段设卡最经济。这个方向的技术效果是减少无效重算次数。

**方向三，把知识身份绑定做成跨库可迁移的稳定标识**。当前的稳定哈希只解决单库内的一致性。可以设计一种与教材版本无关的知识身份标识方案，使得同一考点在不同版本教材、不同题库之间保持同一标识，从而使跨库的学习记录聚合成为可能。这个方向的技术效果最明确：跨库聚合的准确率。

挖掘的交付物不是想法，而是**可实施的方案加可测量的效果数据**。每一项都要回答：解决什么技术问题、用什么手段、比现有做法好多少、好在哪里可以测。

### 6.4 撰写（第 3 至 6 周）

**权利要求树设计**。以 I-1（生成期知识身份绑定）为例，展示一种可操作的写法。

独立权利要求（方法）应当包含以下限定链：

接收教材结构化单元，对每个单元生成与教材版本无关的稳定标识；在调用生成模型时，将稳定标识集合作为约束条件注入，并要求模型对每个生成结果输出概念声明数组，每条声明包含角色标识、所依据单元的稳定标识、概念名称与判定依据文本；在生成结果落盘之前，由不依赖生成模型的校验程序执行一致性检查，检查项至少包括：声明数组非空、角色标识属于预设枚举、存在且仅存在一条主角色声明、主角色声明所依据的稳定标识与生成结果所声明的锚点标识相同、判定依据文本长度不低于预设下限；任一检查不通过则拒绝落盘并将控制权返回生成步骤。

从属权利要求可以覆盖：不同题型对应不同的最少声明数（病例组题不少于二）；声明数组长度上限为四；校验程序为零第三方依赖的纯标准库实现；下游建图时优先采用声明式映射、仅在缺失时回退到文本推断，且两类来源在产物中标注可区分标记；图结构构建后执行有向无环校验，环检测失败则拒绝该图。

**说明书结构**：技术领域、背景技术、发明内容、附图说明、具体实施方式。重点在背景技术与具体实施方式。

背景技术必须写清**现有做法的具体缺陷**，而不是泛泛说"效率低"。可写：现有方案在生成完成后以文本相似度将题目映射到知识点，该映射过程不产生可验证的依据，当映射错误时无法从产物中识别；映射错误的后果是将学习者的掌握度归集到错误的知识点，其危害大于不做映射。

发明内容必须写清**技术效果的可测量形式**。可写：采用本方案后，多标签映射比例由不足百分之五提升至百分之五十五以上；映射解析成功率在门禁约束下不低于百分之九十八；因映射错误导致的掌握度误归集可通过产物中的依据字段直接定位。

具体实施方式必须给**至少两个完整实施例**，且包含对比数据。这是创造性论证的核心弹药，也是当前项目最有价值却尚未被整理的部分。

**撰写红线**：

不得以提升教学质量、提高学习效率、减轻教师负担作为技术效果——这些无法量化，且在审查中会被认定为非技术效果。

不得把提示词本身作为发明点。提示词属于智力活动的规则，单独主张必被驳回；只能作为"约束注入"这一技术手段的一个环节出现。

不得使用"人工智能辅助""智能生成"这类上位表述替代具体数据结构。权利要求中的每个名词都应当能在说明书中找到一个具体的字段、表或文件。

必须给出对比实验。中国审查实践对"算法加技术"的组合，创造性论证高度依赖技术效果的意外性。当前项目已有的数据包括：事后推断与生成期声明的多标签率对比（4.9% 对 55%）、落点行约束的检出率（132 条重点中 30 条未在落点行照录，占 22.7%）、教师重点覆盖门禁的硬事实缺失数（从有缺失到零）。这些数据需要整理成规范的对比表格。

**地域布局**：

| 法域 | 可行性 | 理由 | 建议 |
|---|---|---|---|
| 中国 | 已公开内容不可行 | 宽限期不覆盖 GitHub 公开 | 仅对**未公开增量**申请；已公开内容放弃 |
| 美国 | 可行至 2027-08-11 | 发明人自身公开享一年宽限期 | 主战场，先提交临时申请占位 |
| 欧洲 | 不可行 | 无一般宽限期 | 放弃 |
| 日本、韩国 | 需个案判断 | 日本有六个月宽限期但限于特定情形 | 暂不考虑 |
| PCT | 价值有限 | 进入中欧时新颖性仍按公开日判断 | 仅作美国后续路径的过渡 |

**类型布局**：只做发明申请，方法加系统加设备加存储介质四套权利要求并列。不建议实用新型——软件方法不在实用新型客体范围内。

**组合布局**：建议一核心两外围。

核心一件，主题为 I-1 生成期知识身份绑定，因为它同时具备最清晰的技术问题、最具体的技术手段、最可量化的技术效果。

外围两件，分别为 I-2 证据局部性约束与 I-3 自述元数据独立重算。这两件与核心形成互补：核心解决"数据怎么产生"，I-2 解决"产物怎么被验证"，I-3 解决"验证者的可信度怎么保证"。三者合起来构成一个完整的"可信生成"技术族，未来做 continuation 或分案时有接续空间。

不建议就 T1、T2、T8、T11、K1 至 K4、K7、K10 申请——这些或已公开且创造性不足，或属公知手段组合，投入产出比极低。

**防御性公开**：对不申请的部分（门禁规则集、按版式分流解析、学科检索配置、调度参数标定），主动做时间戳存证并保持公开。这样做的收益是阻止他人在这些方向上获得排他权，从而保护自己免费实施的空间。对开源项目而言，这比申请专利更实际。

## 第七部分 风险与应对预案

专利工作的失败大多不是败在技术，而是败在程序：权属没查清、公开没冻结、许可证没理清、检索没做透。本部分按可预见的八类问题逐一给出预案。

### 7.1 客体适格风险

**表现**：审查员认定权利要求指向"出题的规则和方法"，属智力活动规则，依据专利法第 25 条驳回；或在美国依 Alice 两步法认定指向抽象概念。

**预案**：权利要求不写"生成题目"，写"生成带结构化证据字段的记录并使校验器可在单元级完成一致性判定"。说明书的技术效果部分写计算复杂度的改进（校验范围由文档长度降为单元长度）、存储结构的改进（产物中不存在无定位的断言）、以及系统状态的可重放性（掌握度状态可由流水重建）。回避一切教学效果表述。

### 7.2 自身公开构成现有技术

**表现**：审查员直接引用申请人的 GitHub 仓库或技能包作为 X 类文件。

**预案**：中国与欧洲无解，不投入。美国依 § 102(b)(1)(A) 主张宽限期，需在答复时提交发明人声明与公开日证据（仓库提交记录、Release 发布时间戳、存证包）。注意该例外只排除发明人自己的公开，不排除他人的在先公开，因此仍需通过 D1 至 D6 的比对。

### 7.3 最接近现有技术的阻却

**表现**：审查员以 D1（CN121579658B）单独或与 D2、D3 组合，否定新颖性或创造性。

**预案**：三层论证。第一层，技术问题不同——D1 解决"如何提高命题效率与一致性"，本方案解决"如何使生成期元数据可审计"，后者是前者未识别的问题。第二层，技术手段不同——D1 的评估主体是仿真答题模型，本方案的评估主体是确定性校验程序，且本方案明确否定模型自检的有效性。第三层，技术效果不同——本方案的效果是映射可审计率与多标签率的具体数值变化，D1 未涉及映射可审计性。同时提交对比实验，证明"把裁决者从模型换成确定性程序"不是简单替换，而是带来了非预期的效果（自述偏差可检出）。

### 7.4 开源许可证与专利权冲突

**表现**：MedKit 以 AGPL-3.0 发布。AGPL 第 11 条要求贡献者就其贡献授予专利许可，并禁止在明知的情况下对必要权利要求主张专利以对抗实施者。若就已在 AGPL 下发布的代码申请专利并对实施者主张权利，可能构成违约或触发禁反言。

**预案**：三条。第一，专利不针对已发布的 AGPL 版本的具体实现，而针对尚未发布的改进，权利要求措辞与已公开代码保持可区分距离。第二，考虑双许可模式（AGPL 加商业许可），使商业客户获得专利许可，开源用户依 AGPL 获得许可，两条通道互不冲突。第三，在申请前做一次许可证尽调，确认贡献者范围（若含第三方贡献，专利许可链条需完整）。

### 7.5 权属瑕疵

**表现**：开发过程使用学校实验室设备、导师课题经费，或处于受雇期间，被认定为职务发明，申请权归属单位。

**预案**：在投入申请费用前完成权属核查。查阅入学协议、科研项目合同、设备使用记录。若存在职务发明可能，优先与单位协商权属分配或申请奖励，而不是隐瞒。隐瞒的后果是授权后被无效，且可能承担赔偿责任。

### 7.6 投入产出不匹配

**表现**：软件专利维权举证困难（需证明对方实施了权利要求中的全部技术特征，而对方源代码不可得），诉讼成本高，赔偿额低。

**预案**：把专利定位为**防御性筹码与谈判资产**，而不是主动维权工具。在融资、合作、被诉时作为交叉许可的交换物。若目标是阻止抄袭，著作权（代码与文档）加商标加数据资产保护远比专利有效。

### 7.7 检索遗漏

**表现**：自检级检索未检出更接近的文献，正式审查时被引出。

**预案**：自检检索只用于方向判断，不替代专业检索。在提交前委托代理机构做一次完整的 FTO 与新颖性检索，重点覆盖中文小语种文献与学位论文（这两类在商业数据库中覆盖不全）。

### 7.8 技术已公开导致他人搭便车

**表现**：机制已开源，他人可直接复用而不承担研发成本。

**预案**：接受这一事实，并把竞争维度从"机制保密"转向"数据资产与质量标准"。具体而言：金标准语料、教师重点锚定清单、难度校准表、回归漏洞库这四类资产是不可复制的，且随时间累积而增值；同时把门禁体系做成事实标准（公开规范、提供一致性测试套件），使跟随者必须对齐你的口径，从而获得定义权。

## 第八部分 决策建议

把前面的分析压成三个可选路线，给出推荐组合，并列出国之前必须确认的五个问题。

### 8.1 三条路线对比

| 维度 | 路线 A：美国单点占位 | 路线 B：中国增量申请 | 路线 C：放弃专利，转防御 |
|---|---|---|---|
| 可行性 | 高（宽限期内） | 低（仅限未公开增量，弹药不足） | 高 |
| 直接成本 | 三件临时申请，量级数千美元 | 三件发明申请加代理费，量级数万元 | 存证与商标软著，量级数千元 |
| 时间投入 | 中（需整理交底书与实验数据） | 中 | 低 |
| 保护强度 | 中（美国市场，举证仍难） | 低（范围窄） | 无排他权，但阻断他人排他 |
| 战略价值 | 谈判资产、融资背书 | 有限 | 保障实施自由 |
| 主要风险 | § 101 与显而易见性组合 | 被自身公开打掉 | 无 |

### 8.2 推荐组合

建议采取 **A + C 并行**，放弃 B。

具体而言：

第一步，本周完成止血与权属核查。这一步不做，后面全部无效。

第二步，用两到三周做技术挖掘，把重心从"已完成的系统"转到"尚未实现的下一代机制"。挖掘方向按 6.2 的三条主线推进，每条都要产出可测的效果数据。

第三步，就挖掘出的核心方向提交美国临时申请，同时提交两件外围。临时申请不审查、成本低，用一年时间观察商业化进展再决定是否转正式。

第四步，对不申请的部分主动做防御性公开与时间戳存证，把已公开的机制固化为现有技术，阻断他人在同一方向的排他权。

第五步，同步补齐低成本的知识产权组合：软件著作权登记（代码与文档，两个模块各一件）、商标注册（MedKit 与 MedAgentWork 文字加图形）、以及数据资产的权属声明。

### 8.3 需要确认的五个问题

在启动任何申请动作之前，以下五项必须明确，否则方案无法落地。

**其一，两个仓库的实际公开状态**。medkit 主仓与 medagentwork-skill 子模块已确认公开；MedAgentWork 主仓的可见性需逐项核实（若为私有，则第四部分关于中国新颖性的结论需要整体重估）。核实方式：在未登录状态下访问仓库地址，能打开即为公开。

**其二，目标市场**。如果产品只面向国内医学生，美国专利的实际价值有限，路线 C 可能更理性；如果计划出海或寻求融资，美国占位的价值上升。

**其三，预算量级**。三件美国临时申请加一年后的正式申请，总投入在数万元至十余万元人民币区间；中国三件发明全流程同等量级。预算决定布局件数。

**其四，权属状态**。是否使用学校资源、是否处于受雇关系、是否有第三方贡献者。这一项决定能否以个人名义申请。

**其五，对开源的承诺强度**。AGPL 是公开承诺，转为私有会伤害社区信任。需要在"保持开源"与"建立专利壁垒"之间做明确取舍，双许可是一条可行但需要法律设计的中间路径。

### 附录 D 外观设计路径评估

**两个前提的更正。** 实用新型不可行的真正原因是客体：专利法第二条第三款把实用新型限定为"产品的形状、构造或者其结合"，软件与方法从定义上不在范围内，与是否使用人工智能、是否开源无关。开源影响的是新颖性（第二十二条第二款、第二十三条第一款），人工智能辅助影响的是发明人资格与充分公开。三者分属不同层面，混同会得出"更换专利类型即可规避"的错误结论。

**时间窗同构。** 外观设计同样受第二十三条新颖性约束，第二十四条的宽限期条款对"发明创造"整体适用，外观设计一并适用。GitHub 截图、README 配图、已上线站点、宣传片、分享包均构成公开，且不落入宽限期的三种例外。因此已上线或被公开截图的界面，中国外观设计同样不能申请。

**反向清单。** 审查指南将"与人机交互无关或者与实现产品功能无关的产品显示装置所显示的图案"排除在授权之外，明确列举"与人机交互无关的网站网页的图文排版"。复习资料阅读页属纯图文排版、无实质交互，落在排除范围内；答题卡、薄弱项表、生成进度页、判分反馈等具备明确人机交互的页面才在可授权一侧。

| 标的类型 | 载体写法 | 可行性 | 要点 |
|---|---|---|---|
| 未公开的新版界面 | 带某图形用户界面的显示屏幕面板 | 高 | 唯一干净路径，申请日前不得截图外传 |
| 局部外观设计 | 同上，实线保护、虚线环境 | 中高 | 可只保护单个控件或卡片样式，范围聚焦 |
| 动态图形用户界面 | 名称含"动态"，附关键帧视图 | 中 | 关键帧须唯一确定完整变化过程，必要时补视频 |
| 实体印刷品版式 | 印刷品 | 中 | 复习手册封面与内页版式，常被忽略 |

图标不建议单独申请外观设计：脱离产品的图标在国内难以作为独立载体，宜走美术作品著作权加商标。

**美国设计专利窗口。** 美国设计专利同样适用 35 U.S.C. § 102(b)(1)(A) 的一年宽限期，已上线界面在 2027 年 8 月 11 日前仍可申请。2026 年 3 月 USPTO 补充指南取消了"附图必须描绘显示面板"的强制要求，标题与权利要求写"用于计算机的图形用户界面"即可。设计专利走形式审查，授权快、成本低，保护期自授权起十五年。其相对发明专利最实质的优势在举证：只需比对图片，无需取得对方源代码，而后者恰是软件领域维权最难的一环。

**实操清单。** 一件申请一个设计，相似设计可合案且不超过十项；视图含主视图（界面所在面的产品正投影）、变化状态图（按交互顺序编号）、必要时补使用状态参考图；界面文字不作为保护要素，提交前须去除或虚化；简要说明写明用途、人机交互方式与设计要点；产品名称不得只写"图形用户界面"，须体现用途与所应用产品，仅提交界面视图时须穷举最终产品；走局部设计时以实线标示保护部分、虚线标示环境。

**定位。** 外观设计不应被当作阻止功能抄袭的工具，改配色、挪布局即可规避。其正确定位是视觉识别资产的低成本占位，与商标、美术作品著作权组成一套，防止整体观感被照搬。值得投入的具体标的有三件：沉浸式作答层、错题薄弱项表、判分反馈动效。
