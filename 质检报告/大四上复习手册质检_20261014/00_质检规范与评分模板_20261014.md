# 00 · 章节级质检规范与分报告模板（统一格式契约）

> 所有分片必须严格按本模板产出，便于统一验收合并。
> 流程纪律：**本轮只做质检（只读），禁止修改任何手册/图片/清单文件**；问题全部写入分报告，由编排器统一验收后再进入改进阶段。

## 一、六维度评分标准（每模块逐项打分，5 分制）

| 分 | 锚点 |
|---|---|
| 5 | 完全达标，无需改动 |
| 4 | 基本达标，仅有 P2 打磨项 |
| 3 | 部分达标，存在 1 个以上 P1（重点不全/突出弱/难度问题） |
| 2 | 明显不达标，存在多个 P1 或关键要素残缺 |
| 1 | 不合格：核心 🔴 事实错误、核心模块缺失，或渲染损坏（P0） |

### A 覆盖度
1. 课表讲授章节是否都有对应模块/考点（对照《大四上课程学习章节清单》该科行）；
2. 每病「定义/病因/机制/病理/表现/检查/诊断/鉴别/治疗/并发症/预防」要素是否齐全（按章节学习内容口径）；
3. 题库高频考点（从该科题库 txt 按模块统计高频主题）是否覆盖；
4. 🔴掌握/🟡熟悉/🟢了解三级深度是否恰当。

### B 重点完整
1. 关键诊断标准/数值阈值/分型分级是否完整且**与教材原文一致**（逐字核验，给出教材原文证据）；
2. 每病核心要素齐全；
3. 高频鉴别完整（题库反复考的鉴别不能漏）；
4. 关键治疗（药物/手术/急救步骤、首选药、适应证）完整。

### C 重点突出
1. 🔴🟡🟢 标注与课表要求、题库考频是否对齐（题库高频却标 🟢/未标 = 问题）；
2. 高收益摘要/先行组织者是否明确；
3. 重点是否用 callout/表格/加粗/口诀/ASCII 图等视觉手段突出；
4. 重点与非重点的篇幅/位置权重；
5. 🔴 考点是否标注「为什么重要」（或等价表述）。

### D 可读性与阅读难度
1. 核心层单句目标 ≤60 字（认知负荷；扫描已给粗指标，定位具体超长句）；
2. 是否先结论后细节、先正常后异常；
3. 有无连续大段纯文本（视觉呼吸，目标 3-5 行一断点）；
4. 新术语是否有解释/同义异名；
5. 难度是否适配「临床大四+考研」，前置知识检查是否到位；
6. 表格/图是否符合多媒体原则（图近文、不与正文重复、清晰）。

### E 学习科学/教学有效性
1. 主动回忆区（🔄）质量与覆盖（问题质量、答案形态、是否覆盖核心；注意无题目版定位）；
2. 关键知识复现/口诀（间隔与强化）；
3. D1 第一性原理、D4 决策树是否真正训练临床推理（给因果推导 vs 摆设）；
4. Bloom 层级（记忆/理解/应用/分析）平衡；
5. D3 谱系、D5 概念地图、导航是否建立体系；
6. 陷阱/小结/take-home message 是否到位。

### F 工程规范与 Obsidian 兼容
- **直接引用《00_工程基线扫描_20261014.md》中本册结论**，通读时复核（确认行号与现状一致、是否有漏报）；
- 另需检查：① 附录页码索引是否真实（抽查 ≥10 个页码与正文「（教材P##）」一致、页码非占位）；② 术语表/口诀附录是否完整；③ 配图清单条目与正文占位符是否一一对应（图号/文件名/通道）；④ 有无流程残留；⑤ 清理说明（课表外剔除）是否有残留自相矛盾之处。

## 二、问题分级（P0/P1/P2）

- **P0（必须改）**：① 与教材冲突的客观事实错误（数值/标准/分型/药名/解剖）；② 课表要求的核心 🔴 模块/考点整缺；③ Obsidian/PDF 渲染损坏（禁用标签、标题断裂、图片丢失、裸 ** 泄漏）。
- **P1（重要）**：重点不全（题库高频未覆盖）、🔴 阈值/分型不完整、重点突出弱、阅读难度过高、关键区块缺失、门禁 FAIL/WARN 中的真实问题。
- **P2（打磨）**：命名/格式不统一、个别长句、空行、个别表述优化、图注建议。

## 三、事实核验纪律（B/F 维度的硬要求）

1. 每个模块的全部 🔴 考点，其**关键数值/诊断标准/分型分级/首选药**至少抽 1 条对照教材 txt 原文检索（用 Grep 关键词定位，不得凭印象）；
2. 每模块从题库 txt 中取该模块题（题库按 M{n} 分节），归纳 5-10 个最高频考点，逐一核对手册是否覆盖；
3. 发现冲突时：记录「手册写法（行号）｜教材原文（含章节/页码）｜题库佐证（题号）｜判定」，**证据不充分不下 P0 结论**，标「待核」；
4. 报告中引用教材原文要短（≤80 字），标明教材中的章节/页码线索。

## 四、分报告文件结构（产出物）

每个分片产出一个 MD 文件（命名见下），结构如下：

```markdown

> 教材：{路径} ｜ 题库：{路径} ｜ 参照：章节清单、Agent5 v5.3 规范、工程基线

## 一、总评（本册评分汇总表）
| 维度 | 得分(均分) | 一句话结论 |
| A 覆盖度 | x.x/5 | … |
（A-F 六行）
| 模块数 | 应 x / 实 x | 缺模块：… |
| P0/P1/P2 数量 | P0 n / P1 n / P2 n |

## 二、逐模块评分表
| 模块 | 课表章节 | A | B | C | D | E | F | 总评 | 主要问题编号 |
（每模块一行，给分 + 一句话）

## 三、P0 问题清单（逐条）
### P0-1 【维度】{模块/行号} {问题标题}
- 现状：…（手册原文摘录，≤120 字，给行号）
- 依据：教材原文 / 题库题号 / 规范条目（必给）
- 影响：…
- 建议：…（具体到怎么改）

## 四、P1 问题清单（同上格式）
## 五、P2 问题清单（可表格简列：编号|模块|行号|问题|建议）

## 六、覆盖度与考频对照
- 课表章节 → 模块映射核对表（逐章：在/缺/部分）
- 题库高频考点覆盖表：| 模块 | 题库高频考点（5-10） | 手册覆盖情况 | 缺口 |
- 事实核验记录：| 序号 | 模块 | 手册说法(行号) | 教材原文/页码 | 题库佐证 | 判定(一致/错误/待核) |

## 七、F 维度复核
- 对工程基线本册条目的逐条复核结论（确认/修正/补充）+ 页码/清单抽查结果

## 八、分片结论
- 本分片 P0 遗留情况（必须列出全部 P0 或写「无 P0」）
- 给改进阶段的修改清单（按优先级排序，与问题编号一致）
```

## 六、禁止事项

- 禁止改动任何手册/图片/清单/脚本（只读质检）；
- 禁止生成 PDF、禁止 git 操作；
- 禁止臆造教材原文或题库题号；找不到证据写「待核」；
- 禁止用关键词计数代替通读（命名差异可能导致假阴性，必须看实质内容）；
- 报告一律写中文，路径/行号/教材原文保持原样。
