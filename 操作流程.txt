MedAgentWork 操作流程（DSH 版 · 2026-08-13 重构）
================================================

主流程已迁移至 DeepSeek Harness (DSH)：MedAgentWork 为 DSH 工作区，
5 个角色以 .dsh/skills/ 技能形式存在，编排在主会话完成，无需窗口间复制粘贴。

──────────────────────────────────────────
一、完整批次流程（DSH 主会话）
──────────────────────────────────────────

准备：将教材/笔记/重点放入 输入素材/{科目}/

1. 打开 DSH Web (http://127.0.0.1:3080)，进入 MedAgentWork 工作区，新建会话
2. 输入：「开始新批次：{科目}+{章节}」（如 开始新批次：医患沟通）
   → 编排者回显意图（科目/目标题数/模块划分）→ 你确认
3. 编排者自动执行（无需你干预）：
   - 调用 MedGen（subagent）→ 题库写入 中间产物/{batchID}/
   - 运行门禁：python validate_options.py --batch {batchID}
   - 调用 MedQC → 质检报告写入 质检报告/{batchID}/
   - 运行门禁：python gate_check.py --batch {batchID} --stage agent3_done
   - 调用 MedFix → 修复版写入 最终产物/{batchID}/
   - 运行门禁：python gate_check.py --batch {batchID} --stage agent4_done
   - 调用 MedReview → 复习资料写入 复习资料/
   - 终审门禁：python gate_check.py --batch {batchID} --stage final
4. 你审查产物 → 输入「签收 {batchID}」→ 批次置 APPROVED
5. 手动将金标准题移入 GoldenSet/（仅你操作），运行 python healthcheck.py

──────────────────────────────────────────
二、状态与门禁速查
──────────────────────────────────────────

  python scripts/workflow_state.py --check      # 状态结构校验
  python scripts/workflow_state.py --migrate    # 旧数据迁移（一次性）
  python scripts/workflow_state.py --show batch026  # 查看批次
  python gate_check.py --batch {batchID} --stage auto   # 自动检测阶段门禁
  python gate_check.py --batch {batchID} --clear-halt   # 修复后清除 HALT
  python validate_options.py --batch {batchID}  # 选项质量校验（报告在 reports/validate/）

门禁 BLOCKED → 回退对应 Agent 修复 → 重跑门禁。详见 .dsh/skills/medbatch/SKILL.md。

──────────────────────────────────────────
四、站点发布（Cloudflare Pages · HC-21 最新性契约）
──────────────────────────────────────────

目标：保证「线上内容 == 最新已推送版本」，且页面文案与数据不出现半更新。

发布前置（缺一即拒绝）
  1) git fetch origin main
     → 要求 behind=0 且 ahead=0（本地与 origin 完全同源）
     → ahead>0（有未推送提交）先 git push；否则他人/CI 从 origin 的部署会把线上顶回旧版
  2) 页面一致性门禁（离线）
     python scripts/check_site_freshness.py --offline
     → index.html 的硬编码「N 科 / N 题」文案必须与 REVIEWS_S1 / BANKS_S1 数据数组一致
     → 新增/下线条目时，同一提交内须同步：数据数组 + 分区大标题 + 分区副标题 + 页面统计数字
  3) 站点链接门禁
     node scripts/check_site_links.mjs index.html
  4) 产物形态门禁
     python scripts/verify_produce_rules.py          # FAIL==0

发布
  powershell scripts\deploy_site.ps1                # 自动执行上述前置闸 + 部署 + 后置校验
  （仅本地手动部署：powershell scripts\deploy_site.ps1 -AllowAhead   # 显式逃生阀，会打警告）

发布后置（脚本自动执行；也可手动复跑）
  python scripts/check_site_freshness.py --expect-commit <本次提交>
     L1 本地文案/数据一致 · L2 线上指纹（数组条目数/统计数字/pdf 路径）与本地一致
     L3 线上最新 Production/main 部署的 Source == 本次提交（防被更晚的部署顶替）
  FAIL → 视为部署失败或被顶替 → 告警并重部署；禁止用旧内容覆盖线上更新的版本（先合并再部署）

并发发布：同一窗口只允许一个发布者；发现线上已有更新部署，先 merge 再发布。
